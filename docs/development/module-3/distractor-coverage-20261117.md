## 生成与身份

当前统一工作流使用 `distractor_contract.py` / `distractor_annotations.py`，
版本为 `m3.v3 / m3.option-errors.v2 / m3.annotation-candidate.v7 /
m3.annotations.v7 / m3.checks.v3`。原 `annotations.py` 和 `option_annotations.py`
保留旧产物的契约与来源检查原语；V7 不接受旧 `candidate_errors` 输出作为新候选。

每题三个错误基准选项分别输出状态、具体理由、比较证据、候选和未决点。
只有评估中的 `candidates` 生成原错因父/证据子关系。每段证据内部连续、逐字、
同篇正文且有有效来源时间；多段可以分离。时间仍取旧来源片段，未执行新的核听
就不产生新的准确度或核听通过声明。

三种状态相互区分：

- `SUPPORTED`：至少一条候选，无未决点；每条有个人核验要求。
- `NO_SUPPORTED_CANDIDATE`：空候选、有本项比较理由且无未决点。
- `INSUFFICIENT_EVIDENCE`：空候选、明确未决点，生成状态是 `generation_incomplete`。

合法空结果仍须当版审核；未决可以保存为冻结待核产物，但阻断小样批准、整套审核
提交及入库。词典 24 技能/12 错因及系统编码不变；不设置候选数量门槛。

`rules_manifest` 冻结提示词正文、实际候选 Schema、生成参数、词典和适用代码哈希。
`annotation-candidate-v7.schema.json` 由实际 Pydantic 契约导出，回归检查二者相等。
新方法不能复用旧方法的小样、候选、审核或模型缓存。排队后方法发生语义变化，
生成入口和收费预留入口均停止旧任务；租约 fencing 继续生效。

4096 token 上限与预留继续共用配置，未因结构变长自行提高预算。
`finish_reason != stop` 不接受。结构和证据纠错最多两次，每次独立记账；
不允许靠省略失败候选或清空评估过关。断网、截断和预算门控继续保留原响应/预留。
来源原语使用的扁平证据路径会映射回 V7 比较/候选的实际字段，逐字失败反馈附上
所引片段的原文，避免修复了错误位置。提示词明确个人核验要求为单个字符串、
多 ID 引文须覆盖这些连续片段的完整文本；没有放宽逐字校验。

尚未生成完整小样即失败时，管理端可用 `reprocess_result_hash` 绑定现有冻结来源
显式创建修复子修订。该入口只用于失败的标注阶段，重新生成前五题并复核，
不把来源视作合法空小样，不复用失败候选或批准，也不改写旧响应与费用。

## 修订、持久化与读取

服务端保存每次原始候选及其校验结果，计算新增、删除、重分类、证据和状态变更，
绑定前后哈希与实际调用 ID。新方法首次生成不把历史候选加入反馈；同方法显式
修订才对照父响应。纠错历史进入最终审核的 `candidate_changes` 必审集合，
删除候选也须另行核对材料依据。模型不负责自报可信 diff。

评估表只存过程结论、候选哈希、理由和待核点，不复制候选标签。
比较证据通过独立关联表指向本批次已有证据实体；候选继续使用
`error_question_relations`。新父关系增加 `personal_verification_needed`。

增量迁移兼容 legacy 空选项及 V1 记录，保留旧当前批次、开放和作答。
新规则按事务、复合外键、唯一键及延迟约束检查三项齐全、排除正确项、
SUPPORTED 与候选一致、规则/来源身份、同篇比较证据及有序子证据。
已持久化评估和比较证据不能原地修改，须创建内容修订。
已有最后证据防护与跨表归属约束继续执行。存在新版本审计数据时禁止破坏性降级；
恢复需使用验证过的备份，不删除历史来恢复旧读取行为。

逐题审核必需集合包含全部技能/技能证据、答案证据、候选/候选证据、三个评估、
全部候选删改。缺任何一项就不能整套提交。审核会话继续绑定结果哈希；新修订
全套重审，保存意见不调用模型。真实执行者可明确记录为 `human` 或 `codex`，
Codex 内容复核不替代真人独立审核或原音核听。

统一管理详情、正式管理员标注读取共用投影，展示三项状态、理由、逐段试听、
个人核验要求、删改以及覆盖/resolved/审核数量。学生 DTO 不增加标注字段。
旧方法当前标注返回待重新标注，不回填旧候选，也不改变旧卷内容或学生访问。
