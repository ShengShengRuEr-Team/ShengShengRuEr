# 本套第9—10步及后端全流程

更新：2026-11-07，Asia/Shanghai；需求V2.3，开发V1.9；冻结技术版本V1.2不变。用户明确授权“依旧采用这个规则，然后开发到全线pass”，并确认本套音频已经审批通过。原develop仓库、分支、未提交实现、软件包/模型版本及费用账本均保留。

当前补验：文本和扫描原卷两路均通过完整后端验收，详见[独立交接记录](independent-acceptance.md)。下文早期任务和计数为历史证据。

## 当前流程

1. 从已通过的165句上游、原件组装、小样及25题整套候选开始；核验原件、产物、适用实现、提示词/词典和逐题复核哈希。上游复用不冒称新推理。
2. 管理员显式创建`stop_after=completed`。自动原文路线须同时绑定reuse_alignment_task_id、reuse_assembly_task_id、reuse_annotation_task_id/sample_review和reuse_full_annotation_task_id/annotation_review。未通过整套复核不得用入库请求偷偷继续收费修复。
3. API从核验后的trusted_question_structure取得原卷独立题量及题组，检查1—25完整覆盖、原卷哈希/存储键及申报冲突。新字典对象写回JSONB，冻结请求后计算input_hash，避免内存原地修改未持久化的缺陷。
4. 独立worker重核上游、组装及全部候选，执行业务validate和pending入库。此时不改变旧当前版本、原音绑定或可见状态，不自动签复核通过。
5. 显式POST任务checks：业务最低内容检查、草稿规则和来源哈希分别执行。内容复核覆盖25题；标注复核逐项覆盖全部技能/错因/答案关联。
6. 音频复核支持两种明确依据。itemized沿用整套已核听及140正文句独立起止参考、各端≤300ms。user_confirmation仅用于用户明确批准的音频，要求审批来源、当前结果哈希和原音哈希；保存用户原话，不填写虚构的reference_start_ms/end_ms，不声称独立测量。
7. 审核状态按本批次、本scope同步到对应业务行；三类复核和检查通过后任务completed。原件草稿和已冻结hash保持不变，共享词典审核状态不被批次审核改写。
8. 管理员单独POST current-batch，绑定task/batch/check/result_hash及expected_current_batch_id；缺审核、学生身份或冲突均拒绝。新当前批次默认隐藏，重复确认不清除已确认可见状态。
9. 再独立POST visibility confirm，模块二学生接口只返回题干与选项，管理员配套接口读取正文、原卷答案/解析及M/W。取消可见后新的学生列表、详情及音频请求均拒绝。
10. 核查原音全文件哈希、Range和解码，逐项核对25题/100选项/165句回读、幂等重导及重启后持久状态。错因有依据才保留；文本路径1项、扫描路径3项分别经来源复核，不按题量补标签。

## 实跑与复现

`backend/scripts/review_module3_full_pipeline.py`固定使用原有隔离验收库`m3_auto_real_20261106_124443`，音频写入本轮受控输出目录；不重置数据库，不更改正常应用数据库URL。通过本机127.0.0.1:8813启动临时Uvicorn并执行真实TCP HTTP，独立ASR环境worker执行入库。脚本结束会停止临时服务；这不属于部署。

运行：在backend使用`.venv-api/Scripts/python.exe scripts/review_module3_full_pipeline.py`。每次保存独立tcp时间目录、请求/冻结请求、worker/API日志、方法快照、检查与复核、回读、幂等任务及报告。正常重复运行会新增审计任务；方法变更可能产生新历史批次，同方法相同结果复用已有批次。费用失败与预留不清零，本轮无需新增DeepSeek请求。

真实运行及所有最终检查见验收报告（历史本地资料，随验收证据另行交接）。第7—8步原始草稿、失败与修订仍在此前证据（历史本地资料，随验收证据另行交接）。

## 适用范围

本套输入为文本原卷PDF、真实扫描答案解析PDF和本地原音。PASS限定实际套别、版式、冻结环境及后端链路。可选错因允许为空；用户音频批准与量化基准分别记录。未扩展为任意扫描版式、所有ASR输入或教学盲审准确率承诺；本轮不开发前端、不提交、合并或部署。
