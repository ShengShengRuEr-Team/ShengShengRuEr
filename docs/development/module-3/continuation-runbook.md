# 模块三统一管理端操作说明

## 启动

按[冻结版本约定](technical-version.md)分别使用 API、ASR、OCR 环境。API 与 Worker 读取同一个数据库、材料目录、产物目录及音频目录，不在 API 环境混装模型依赖，不将业务库指定为测试库。

1. 备份待升级数据库，在 API 环境、`backend/` 下执行 `python -m alembic upgrade head`。
2. API 环境运行 `python -m uvicorn app.main:app --host 127.0.0.1 --port 8000`。
3. ASR 环境独立运行 `python -m app.module3.worker`，单次处理用 `--once`；`M3_OCR_PYTHON` 指向独立 OCR 环境。
4. 前端默认5173，从原登录进入“题库管理 → 上传材料/处理任务”。

处理前配置 `M3_ASR_PYTHON`、`M3_OCR_PYTHON`、`M3_MODEL_ROOT`、`FFMPEG_DLL_DIR` 和 `NLTK_DATA`。收费阶段使用受控模型密钥，不放入页面参数、校正文件或提交记录。

## 正常处理

确认试卷身份、文本/扫描模式及实际听力页码，分别上传原卷 PDF、同套答案解析 PDF 和原音。三者验证后显式开始。

对齐完成后结合原音逐项核听，填写实际依据并保存确认，再显式继续。来源阶段依据原件核对题干、选项、答案与解析；前5题试标确认后才继续整套生成。

最终审核页只读内容。逐题保存内容、技能、答案证据和每条错因/证据的意见，无有依据的错因也须明确确认。退回时定位问题并填写原因。保存意见不调用模型；新版本整套重新审核。

当前最终版本的逐题审核和实际核听确认完成后，“正式入库并激活”。新批次仍不向学生开放，须到正式详情独立“确认开放”；撤销开放也是独立操作。

## 进度与计时

任务详情顶部显示当前正在做什么、当前步骤进度和本次任务用时。OCR按当前任务清单及实际完成的页面结果计数，页面渲染不计为识别完成；有可信总数时显示比例，没有总数时显示不定进度，不估造完成百分比。生成阶段计入可核实的小样/历史候选复用及本轮实际写入候选。

进度每5秒读取一次，用时在有效执行期间每秒更新。等待人工确认、停止或租约过期时暂停；刷新后沿用服务器记录的任务用时。计时针对本次处理任务，进入下一任务会重新计时，不将人工等待时间并入执行用时。

阶段核对支持全选/取消全选。“统一核对依据”可以应用到全部或只填空白项，之后可逐项修改；批量填写不自动保存批准或继续下一阶段。

## 中断和恢复

- 操作丢响应时保留本地提示，先查询原操作。恢复时使用原键、原请求和原版本条件，不自动换键。
- 上传不做字节级续传。中断/租约过期后重新选择文件，保留其他 ready 材料。处理后材料冻结，先建立子修订再替换。
- 停止撤销所属执行权，只终止所属子进程树。迟到旧结果不能写回；租约失效不会自动再次发送付费请求。先核对账本，再显式重试。
- 发布失败核对 pending 检查点，携带原发布操作 ID、同一最终哈希/审核会话及当前批次条件重试，继续校验已有 pending 批次。准备失败不会切走旧当前卷。
- 正式批次变化时整体刷新详情，不能继续用旧页面操作新批次。

生成阶段显式重试会逐题核验失败任务保存的原始成功响应、题目依赖、完整请求及候选规则，有效项复用原调用记录，无效项重新请求。多次重试保留可追溯的祖先产物链，不追加重复费用，也不自动批准小样或最终结果。仅兼容的 Worker 运行修复可建立新修订并引用真实核听/来源审批；字典、提示词、校验和选项算法变化仍须按新方法处理。

`WORKER_LOST` 表示执行租约过期，先检查该操作的 Worker 日志及心跳，不应直接认定模型错误。独立 Worker 启动必须注册全部外键引用模型；生成路径不能依赖 API 或对齐阶段的间接导入。`LLM_TRANSPORT` 且存在未知计费时，保留请求时间、调用记录和预留，依据供应商实际账单核实；刷新、服务重启及重复点击均不能清零或自动续费。没有账单事实时保持阻断。

## 受控来源校正

固定识别错误不通过反复标注模型解决。审核页保持只读，由管理员在受控目录准备实际校正文件，通过 API 环境、`backend/` 下的工具提交：

```text
python -m scripts.correct_workflow_source --workflow <workflow_uuid> --file <patch.json>
```

实际管理员令牌通过 `M3_ADMIN_TOKEN` 环境变量提供，不放在命令行或文件内。工具要求 HTTPS 或本机 HTTP，保留原键/原请求的 `.operation.json` 恢复记录，同一恢复记录不能换内容；校正文件和恢复记录均保留在私有目录。

普通来源文件遵循 OpenAPI 的 `SourceCorrectionRequest`，包含期望工作流版本、修订、父结果哈希、原因和 changes。每项提供题目、白名单字段、期望前值、新值、本修订材料 ID、实际页码及定位。允许题干、基准选项、来源答案和解析，禁止标签、理由、证据和手填时间。

未生成最终结果的来源确认阶段，父哈希取该阶段 GET 返回的 `result_hash`。校正建立子修订并保存前后值/操作者，再确认来源、按依赖处理试标和整套生成，最终整套重审。旧自动初稿与意见保留。

原文/对齐问题使用 `--alignment`，遵循 `AlignmentCorrectionRequest`：原对齐产物哈希、实际原件依据、逐句来源列表。每句提供原文件哈希、相对存储键、原页和搜索范围。服务端重新计算边界，不接受已对齐的 `start_ms/end_ms`，也不能修改模型候选。

## 局部标注修复

先保存具体问题，展开“退回后局部重生成”，选择题目并填写反馈。预览显示生成题数、整套审核题数和小样影响；执行须匹配当前 `plan_hash`，范围或方法变化须重新预览。

依赖比较通过可复用实际小样产物和审批引用；前5题、正文/对齐或共享方法变化则重做相应门控。新最终结果始终建立空审核会话。同原音历史重试及未知计费继续累计，不重置额度。

## 复验

```text
python -m scripts.verify_module3 --suite api
python -m scripts.verify_module3 --suite all --asr-python <冻结ASR解释器> --ocr-python <冻结OCR解释器>
python -m scripts.verify_continuation
```

验证器新建并清理自己的隔离库。桌面合成交互脚本 `tools/verify_processing_browser.mjs` 通过环境变量指定已有 Playwright 和浏览器，不引入运行时依赖。合成结果、构建和单测不能代替指定两路真实材料的核听及语义验收。
