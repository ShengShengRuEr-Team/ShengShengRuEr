## 1. 交付边界与开发顺序

仅在现有桌面题库管理中扩展，不新建工作台。本轮支持四级、六级标准完整真题；不扩展非标准练习卷、身份校正页面、学生个人错因诊断、第三家模型或自动择优路由。

开发顺序固定为 P0 → P1 → P2 → P3 → P4 → P5 → P6。双供应商接入属于 P4，模型相同率属于 P6；P0—P5 可独立验收，不能要求先产出对比报告才能交付题库管理。完整需求交付仍包含 P6，不将延期解释为取消。

| 阶段 | 开发内容 | 阶段完成条件 |
| --- | --- | --- |
| P0 | 契约、存量盘点、增量迁移骨架与隔离环境 | 当前迁移头、旧流程版本、自然身份、预算归属和历史来源可追溯；不改写历史结果 |
| P1 | 管理员列表、唯一当前草稿、内容增删改查、归档恢复 | 人工建卷及已发布卷修订可保存，正式批次不被编辑覆盖；归档与作答交互符合要求 |
| P2 | 人工技能、错因、三项评估、证据及来源重建 | AI、人工、混合来源可确定性重建，严格校验；保存不调用模型 |
| P3 | 版本差异、保护清理、完整和局部回退 | 最新与上一版本受保护；七天计时、引用保护、并发与回退成立 |
| P4 | 新流程、旧任务过渡、双供应商、候选采纳与预算 | 核听合并来源审核、取消试标；官方适配与账本可用，重生成不覆盖人工内容 |
| P5 | 审核、入库激活、独立开放、统一页面联调及回归 | 全部非对比功能形成可验收闭环，保留学生权限、同卷限次和历史快照 |
| **P6：最后实施** | **双模型相同率计算、真实 25 题独立运行、分歧核对与报告** | **完成固定分母统计与如实披露的报告；不降低正式入库门控** |

P0—P5 只预留模型身份、候选及调用记录等必要数据，不提前建设统计页面、相同率算法或批量对比执行器，也不提前启动整套双模型收费评测。

## 3. 身份、草稿与存储模型

### 3.1 身份与版本边界

| 对象 | 标识及生成边界 |
| --- | --- |
| 稳定试卷 | 既有 `exam_paper_id` 与自然身份 `exam_level + exam_year + exam_month + paper_set + content_scope`；无正式批次的人工草稿也先登记稳定身份，不进入学生列表 |
| 工作流修订 | 既有 `revision_id` 表示冻结来源和方法上下文；冻结后改变依赖或方法建立子修订，历史只读 |
| 当前编辑头 | 每卷唯一 `edit_head`，指向当前修订与最新保存版本；所有管理员共享，独立评测修订不取得编辑头 |
| 保存版本 | 每次有效、明确保存形成 `save_version_id / version_no / parent_version_id`；跨修订保持同卷单链，回退和采纳也追加到链尾 |
| 模型候选 | 独立 `candidate_id`，绑定题目、依赖、方法、原始产物及 receipt；逐题检查点不生成编辑保存版本 |
| 最终结果 | 服务端重建、校验并冻结的 `final_result_hash`，绑定保存版本、来源清单及方法；审核和入库均检查该身份 |
| 正式批次 | 既有 `batch_id`；与最新保存版本独立，新草稿不会切换当前批次 |

自动生成结束先形成独立候选；管理员采纳后生成保存版本。人工建卷首次有效保存生成 V1。相同规范化内容的重复保存返回现有版本，审核意见和只读访问不推进版本。候选生成事件可记录“模型生成”，不自动挤占最新与上一保存版本的保护位置。

题目、篇章、句子使用修订间稳定的源身份；正式表自增 ID 通过映射关联。新增对象分配 UUID，题号和展示选项字母不是对象身份。编辑器同时显示基准选项与展示选项，标签始终绑定基准选项。

## 4. 状态机与旧任务过渡

### 4.1 `library.v1` 新流程

```text
材料齐备 → extract/OCR → align → assemble
    → awaiting_source_review（来源审核 + 实际核听）
    → annotate_all（逐题检查点；无前五题停点）
    → local_validate → candidate_ready → 显式采纳为保存版本
    → awaiting_final_review → reviewed → pending_import
    → activated_hidden → 独立开放
```

人工路线：创建草稿 → 保存内容 → 来源、核听及结构检查 → 人工标注或 AI 候选 → 保存/采纳 → 本地完整校验 → 整套审核 → 同一入库链路。人工路线记录真实本地组装执行和人工来源，不创建虚构模型 receipt。

流程、编辑、来源审核、最终审核、发布、开放与归档分别显示状态。上述为语义状态，实施时通过 DTO 映射既有字段，不把全部状态塞入一个“完成”字段。

| 转换 | 服务端条件与行为 |
| --- | --- |
| 对齐 → 组装 | 自动检查有效产物与执行权后排队，无独立核听批准；缺原文仍要求显式 ASR 或补材料 |
| 来源审核 → 整套标注 | 原件、标准卷完整性、来源答案、原文、对齐问题处理及真实核听全部满足；批准绑定依赖哈希，不自动标记已核听 |
| 标注中失败 / 重试 | 保留成功题、失败候选和账本；管理员选定范围，仅复用同依赖、同方法的合法结果；不得默认重跑全部 |
| 编辑 / 采纳 / 回退 → 待审 | 有效变更追加保存版本，整套最终审核失效；来源审核按依赖影响表判断是否失效 |
| 最终审核 → 发布 | 整套逐题结论与当前结果哈希一致，完整来源合法、无未决点且执行权有效 |
| 激活前 | 新修订待审、待激活或失败时，旧当前批次及其有效开放保留 |
| 激活成功 | 事务内切换唯一当前批次，新批次默认不可见；允许到独立开放前暂时不可访问或新提交，界面先提示影响 |
| 幂等重复激活 | 若同批次已激活，返回原操作；不得再次清空该批次已取得的独立开放确认 |

### 4.2 旧任务采用显式分流

旧修订继续按 legacy 流程恢复，历史 `align`、`sample`、批准、候选和账目原样保留。新增或显式升级修订才使用 `library.v1`，不能仅改全局 `NEXT_STAGE` 让旧数据失去语义。

管理员选择升级旧暂停任务时：先停止并撤销原执行租约，创建注明升级原因的子修订；校验依赖后复用合法对齐和组装。原独立核听记录可以作为来源审核证据，但须补全来源确认；旧小样只在输入、规则、方法完全匹配时作为逐题缓存复用，不能充当新流程小样批准。无有效记录的范围仍待核听或标注，费用累计不重置。

同步修改编排器、Worker 的前五题分组、恢复器、重处理预览、能力接口、进度展示与阶段按钮。旧路由仍能读取历史，不为新流程生成假 `sample` 产物或假批准。

## 5. 内容编辑、依赖失效与人工重建

### 5.1 保存与校验层次

保存接口接受完整编辑快照和变更范围；服务端核对对象归属并计算实际差异。缺少题干、完整题量、唯一主要技能或完整三项评估等可保存为缺项草稿，响应列出字段级 `issues`，不生成有效通过结论。非法词典编码、越权引用、跨篇证据、引用不存在对象或向正确项挂错因直接拒绝。

送审要求标准完整真题、题号和映射合法、每题恰好一个 PRIMARY、合法 AUXILIARY、独立答案证据、三个错误选项评估齐全。`SUPPORTED` 必须有证据候选且无未决点；`NO_SUPPORTED_CANDIDATE` 必须空候选、明确比较理由且无未决点；`INSUFFICIENT_EVIDENCE` 必须保留未决点并阻断通过。删除最后一条错因须选择合法空结果并填写比较理由，或明确标记依据不足。

错因去重键为“题目源身份＋错误基准选项＋编码”，同关系允许保留多个独立证据组，不误合并不同选项。证据只允许本篇有效 BODY 句子；多句按连续有序正文全文拼接，单句允许连续子串。时间从有效对齐派生，不接受任意时间戳覆盖。

### 5.2 依赖失效矩阵（DEV-03）

所有下列有效变更都使**整套最终审核**失效。表中其他列表示最低重校验范围；无关题和来源记录可在哈希验证后复用。

| 修改对象 | 对齐 / 来源与核听 | 标注、映射和证据处理 |
| --- | --- | --- |
| 题干、解析 | 音频/正文未变可复用；来源识别内容变化需重做该题来源核对 | 该题全部标签和答案证据重新验证，旧候选标记依赖失效 |
| 选项内容、顺序、正确答案 | 正文未变可复用核听；来源答案与映射重新核对 | 重建基准/展示映射，重验该题技能、答案证据、三项评估和错因归属；禁止只换字母 |
| 篇章正文、句子内容或分句 | 重做受影响篇章对齐、来源核对与核听 | 本篇关联题证据与候选失效；不自动沿用旧句 ID 与时间 |
| 说话人 | 检查对齐输入是否包含说话人；包含则重对齐；受影响范围重新核听确认 | 该句及依赖说话人的题目标注重新验证 |
| 音频文件 / 对齐搜索范围 | 重对齐受影响音频关联范围并核听；全卷音频替换默认全范围 | 重建片段时间、证据及依赖该范围的候选有效性 |
| 人工技能、错因、评估、证据 | 来源依赖未变可复用核听；试听不改变状态 | 重验受影响关系和关联约束；不强制调用模型 |
| 增删题目、篇章、句子 | 展示受影响引用；重新检查完整真题题量与来源范围 | 拒绝悬空关系或要求显式一并删除；不因删题调低应有题量 |
| 词典、提示词、模型和参数 | 纯方法变化不重做无关来源核听 | 新方法候选独立生成；旧停用编码可查看，送审按当前规则重验 |

服务端统一 `dependency_manifest`，覆盖材料、题目、原文分句、音频、对齐、选项映射、词典和方法。变更预览返回需重做的范围、可复用记录和关联约束；保存不自动启动收费生成或重对齐。

### 5.3 最终产物来源

按“冻结来源＋选定 AI 候选（如有）＋按序人工修订”重建最终快照，校验 `parent_hash → content_hash → final_result_hash`。来源类型使用 `AI / MANUAL / MIXED`，每个字段或关系可追溯到真实来源。

AI 部分仍验证原请求、响应、模型身份及 receipt；人工部分验证操作人、前后值、原因、证据和父哈希。纯人工结果只要求真实的本地组装/校验执行记录，不要求模型回执。现有最终任务与产物绑定通过真实本地执行保持，不造模型任务冒充调用。审核、缓存、恢复、入库与回读采用同一来源验证器，不能只放宽最终发布函数。

## 6. 保存、候选采纳、回退与版本清理

### 6.1 统一写入协议

1. 管理员鉴权后，按 `Idempotency-Key` 查询原命令；同键同请求返回原结果，同键异请求返回冲突。
2. 获取试卷锁，再锁工作流及编辑头；清理、归档、提交准入、发布沿用同一锁顺序，避免锁循环。
3. 校验 `expected_row_version / expected_content_hash`、当前修订、归档与任务状态。过期返回 409，附最新版本和差异入口，不静默覆盖。
4. 服务端计算规范化差异和依赖影响，校验关联范围；内容无变化时不新建版本或触发费用。
5. 有效变更须非空原因，原子写入快照、修订记录、新编辑头、审核失效及保护时间，提交后返回结果。

正在执行或发布时，拒绝不兼容写操作并返回冲突任务。停止为独立明确操作：撤销租约并等待停止确认后重试编辑。失去 fencing token 的 Worker 不得继续调用模型、写产物或激活；停止前已发出的外部请求仍如实记录费用及返回。

### 6.2 候选与局部采纳

重新生成、换模型及 P6 评测都只写候选。采纳预览比较候选与当前保存版本，提供技能、具体错误基准选项、证据及内容范围的差异。服务端返回必须联动处理的依赖，例如答案变动必须重审三个错误选项，不能把范围外主要技能顺带替换。

采纳请求绑定预览的当前版本、候选、范围、依赖哈希和原因。再次校验后形成新保存版本；未选择内容保持原值，旧人工记录和候选不删除。候选依赖过期则拒绝或要求重新生成，不能机械叠加人工补丁。单纯生成或查看候选不改变编辑头、审核、正式批次或开放状态。

### 6.3 回退

完整回退或选择题目内容、技能、错因和证据范围，均先预览差异与影响。执行时核对快照可恢复、当前版本、词典、材料、映射及对齐依赖；局部恢复需要包含所有必需关联。成功追加新版本并记录 `restored_from_version_id`，整套重审；失败不改变当前或正式版本。恢复不调用模型，后续重处理需另行显式启动。

### 6.4 七天保留与清理

最新和紧邻上一保存版本长期保护。保存 V5 后，V5/V4 受保护，V3 的 `unprotected_at` 设为本次服务端时间，最早在七个完整 24 小时后成为清理候选。时间存 UTC 并带时区，页面按用户时区展示；引用解除不抹去原审计时间，重新进入保护再退出时从新的退出时间计时。

清理分为候选扫描和执行复核。执行获得同卷锁后，重新检查最新/上一版本、正式批次、历史作答快照、审核依据、活动任务、模型来源、回退和共享引用。存在任一保护即跳过。先标记不可恢复并记录清理命令，再幂等清除允许删除的完整恢复快照；不清理仍为修订来源证明所必需的前后值、模型原始产物、账本或共享材料。

保存、回退、发布和新建业务引用也必须在相同锁下检查快照状态，不能对已不可恢复对象新建恢复依赖。页面始终保留版本摘要、保护原因、期限和清理记录；过期且已清理版本移除回退按钮。

## 7. 归档恢复、批次切换与学生作答

归档预览返回材料、当前批次、草稿、活动任务及作答关联数量和影响。执行要求原因、版本和幂等键；有活动处理或发布时先停止或完成，归档与最终激活互斥。归档是逻辑操作，不删除稳定身份、历史版本或本地浏览器草稿。

学生可新访问或提交的条件增加 `not archived`，同时继续满足当前批次、最低内容检查、独立开放和同卷限次。归档与新提交准入按同卷锁线性化：归档先提交则拒绝新准入；服务端先完成接收并持久化幂等提交则继续得到确定结果或查询状态。先查询已有提交再判断新准入，不能把重放当作新的作答。

恢复清除归档状态但不自动开放，当前批次需重新独立确认。稳定身份和历史次数不变；旧本地草稿保留，但提交时重新检查原批次、题目、当前开放和版本，不保证旧草稿可以直接提交。历史结果读取按原权限及快照，不借归档或恢复扩大答案、音频、原文或错因访问。

编辑已发布卷只产生待审修订；pending 入库失败不影响旧当前批次。新批次成功激活后旧批次只留历史，不承诺继续读取旧卷；新批次开放前明确提示暂停访问和新提交。发布版本的自然身份普通编辑不可写，登记错误仍沿用受控后台校正。

## 8. 管理员接口契约

统一 `/api/v1`、`snake_case`、`{code,msg,data}`；所有新增管理和材料接口使用 `require_admin`。以下为目标路径，既有等价入口优先扩展，联调后同步 OpenAPI，不重复建设同功能路由。`W` 表示 `/admin/processing-workflows/{workflow_id}`，`P` 表示 `/admin/listening-papers/{exam_paper_id}`。

| 方法与路径 | 请求要点 | 返回及失败条件 |
| --- | --- | --- |
| `GET /admin/listening-papers` | `page/page_size`、等级/年月/套次、处理/审核/开放/归档状态、关键词 | `items,total,page,page_size`；每项含稳定身份、题量、当前批次、最新编辑版本及分开显示的状态；有界查询避免逐卷补查 |
| `POST /admin/listening-papers` | 标准卷身份、可信题量来源、人工/上传模式、幂等键 | 201 返回稳定卷和工作流/编辑头；重复身份 409 并返回已有对象入口，不另建同卷 |
| `POST P/edit-draft` | 期望版本、原因 | 获取唯一编辑头；已冻结正式结果则创建可编辑子修订，已有编辑头返回该头 |
| `GET W/edit-draft` | 可选保存版本 | 快照、缺项、映射、依赖、行版本和内容哈希；历史版本只读 |

| `PUT W/edit-draft` | 快照、范围、原因、期望版本/哈希、幂等键 | 新保存版本或幂等原版本、缺项与影响；409 冲突，422 非法引用/编码 |
| `GET W/versions`、`GET W/versions/{id}` | 分页 / 目标版本 | 历史摘要、恢复能力、保护原因；清理后仍能读取摘要 |
| `GET W/versions/{id}/diff` | `against_version_id` | 逐题、逐字段及关系差异；跨卷引用拒绝 |
| `POST W/restore-preview`、`POST W/restores` | 来源版本、范围、期望版本；执行另带原因和幂等键 | 预览影响 / 新保存版本；快照不可用返回 410，依赖过期 409，不覆盖正式批次 |
| `GET W/candidates`、`POST W/candidate-adoption-preview` | 方法、题目范围 / 候选与选择范围、当前版本 | 候选原始结果与人工差异、关联约束 |
| `POST W/candidate-adoptions` | 候选、显式范围、依赖和当前版本、原因、幂等键 | 新保存版本，未选择范围保持不变；依赖失效 409 |
| `POST P/archive-preview`、`POST P/archive`、`POST P/restore` | 预览目标；执行带版本、原因与幂等键 | 关联影响 / 归档或恢复状态；有不兼容任务 409；恢复不可自动开放 |
| 既有 `W/start / continue / retries / stop / stage-approvals` | 增加流程版本能力与方法选择；重试明确题目/选项范围 | 202 命令及既有 operation 查询；新流程禁用 sample 门控，拒绝来源未审标注 |
| 既有审核、`W/reprocess-preview / reprocess / publish` 与可见性接口 | 绑定保存版本、结果哈希及操作版本 | 整套审核、候选生成、发布和独立开放仍分开；过期审核 409 |

篇章、句子、题目和标注的增删改通过快照差异统一提交，服务端完成删除影响校验，不另设可绕过版本的直接正式表 CRUD。列表返回未发布草稿，但学生列表不返回；筛选和关键词服务端分页，稳定按修改时间和 ID 排序，索引依据查询计划添加。

通用写请求除首次创建外带 `expected_row_version` 与 `expected_content_hash`，变更带 `reason`。同一操作复用幂等键；冲突后产生的新操作使用新键。长操作返回 `operation_id`，继续使用现有操作查询和断线恢复，不依赖浏览器连接。

错误区分 401 未登录、403 无管理员权限、404 不存在或学生不可见、409 状态/版本/幂等/依赖冲突、410 快照已不可恢复、422 内容非法。上下文沿用项目 `AppError` 契约，至少含对象、问题路径、最新版本和允许操作，不向学生泄露管理端内容。模型调用失败记录在操作详情，不伪装为成功空结果。

## 9. 双官方供应商与预算（P4）

### 9.1 适配与方法冻结（DEV-06）

默认 DeepSeek 官方 `deepseek-flash`，替代阿里云百炼官方 `qwen3.8-flash`。模型名来自已确认需求；本文未重新验证供应商当前可用性、价格或全部参数。实施接入时查官方文档、核对账号地域及实际响应，再冻结配置；若指定模型不可用，明确报告接入阻塞，不能自行换型号。

当前本地 DeepSeek 参数为关闭思考、`temperature=0`、`max_tokens=4096`、JSON 对象输出、不流式，HTTP 超时 120 秒。新适配器以保留业务约束为原则，不能假定千问接受同名参数。

| 配置项 | 落实规则 |
| --- | --- |
| 服务与模型 | `provider / official_endpoint_id / region / requested_model / response_model / resolved_version`；仅使用服务端官方端点白名单，客户端不能传任意 URL |
| 参数与并发 | 冻结思考模式、采样、输出容量、超时、并发及纠错次数；继续单处理并发，每题初次请求后至多两次显式登记的自动纠错，禁止 HTTP 层再叠加隐式重试；正式接入若既有有效限制更严则保留更严值 |
| Schema 与提示词 | 本地完整业务 Schema 和供应商兼容 Schema 分别版本化；统一语义输入、词典和 V7 提示词，供应商包装单独留痕 |
| 方法哈希 | 纳入上述配置、提示词/词典/Schema 哈希、适配器和校验代码版本；输入与方法共同参与缓存键 |
| 原始证据 | 保存脱敏后的实际请求、响应、结束原因、用量及 receipt；密钥、鉴权头不落库、不返回、不写日志 |

统一适配结果包含候选、原响应引用、完成状态、拒绝/空输出/截断/JSON 错误/限流/超时/本地校验错误、用量与账本引用。结构及来源错误可有限纠错，每次均登记；语义删除不得靠清空候选通过。进行中固定方法，切换创建新修订，新结果独立候选且需显式采纳。

### 9.2 预算键与费用（DEV-01）

沿用单套累计不超过 2 美元、既有阶段总累计不超过 5 美元。新流程不使用前五题小样额度控制前五题，但旧 sample 账目继续累计。双供应商、修订、自动纠错、显式重试、候选重生成和 P6 评测均不能重置上限。

预算使用稳定 `budget_scope_id` 对应既有总累计范围，`paper_budget_key` 对应规范化同卷身份。所有同卷修订和供应商共享单套键；切换工作流、模型或数据库执行目录不另获额度。迁移建立历史 `run_key` 到稳定键的可审计映射，纳入现有外部历史账本；归属无法确定时先保守计入总账并核对，不丢弃记录。

每次调用在共享预算锁内完成“检查余额＋最大可能费用预留＋写 attempt”，然后再次检查执行权再发请求。预留按该供应商输入、最大输出、缓存和适用思考计费项目计算；计价未知且无法做可信最大预留时拒绝发出该次收费调用。人民币等原币费用保留原值、价格版本、汇率来源/生效时刻，以保守换算美元额检查预算；不能套用 DeepSeek 单价。

未知扣费保留原状态，按预留计入；已知用量计算标记估算，供应商确认才标记实际。结算以该 attempt 的已知或预留值替换其预算占用，不把同次调用重复相加。未知状态不单独禁止显式重试，但新增预留必须仍在累计预算内。预算不足保留已完成结果并显示未执行范围，不自动追加预算。

## 11. 最后阶段：双模型相同率与报告（P6）

本节设计现在保留，**实现、真实对比调用和报告均在 P5 完成后执行**。以 2025 年 6 月 CET4 第 1 套真实 25 题、75 个错误选项为固定样本；来源和实际核听先完成。两方共享冻结题目、基准映射、正文、词典和业务提示词，分别独立生成，不给另一方标签，不混入人工修订。候选只读保存，不占用唯一编辑草稿。

### 11.1 有效性粒度（DEV-05）

统计以指标所需字段及其全部依赖为有效性单位，输出每个单位的 `valid / invalid / insufficient / not_executed` 和原因。整体 JSON 无法解析或关键题目身份不可信时，该题全部指标无效；可解析且合法主要技能及其证据不受某一错因失败影响时，主要技能可单独有效。完整技能必须角色、编码、唯一主要技能和全部技能证据合法；某错误选项必须状态、候选、比较理由、证据及来源完整合法才有效。整题仍不能因局部指标有效而入库。

| 指标 | 相同分子 / 分母 |
| --- | --- |
| 主要技能 | 双方主要技能单位均有效且编码相同的题数 / 固定 25 |
| 完整技能 | 双方完整技能单位有效且 `(code, role)` 集合完全相同的题数 / 固定 25 |
| 错因 | 双方选项单位有效且错误编码集合完全相同的数量 / 固定 75 |
| 非空错因 | 至少一方具有合法非空集合的选项组成分母；仅双方单位有效且集合相同进入分子；另一方失败仍占该非空分母；分母为零显示“不适用” |

非法重复关系必须先报错，不能靠集合化抹去。双方合法 `NO_SUPPORTED_CANDIDATE` 空集合可以相同；失败、漏标、依据不足和未执行均不算空集合，不进入相同分子，也不缩小固定整体分母。三个干扰项状态另列对照，理由文字和引文长度不参与标签集合相同判定，但证据仍必须合法。

### 11.2 执行与交付

在既有预算和有限纠错内逐题运行并保存首次结果、纠错过程、最终模型候选、实际方法和费用。若预算、前置条件或接口失败阻止剩余执行，仍列明全部 25 题 / 75 选项，不用人工值填补。报告可以带失败项验收，不能据此认定对应试卷可入库。

P6 新增独立比较服务和测试，输出机器可读明细 JSON 及 Markdown 报告，展示分子/分母和比例、逐题/选项标签、校验状态、首次通过率、纠错数、模型身份、费用、耗时、失败与未执行原因。分歧人工意见独立列出，不改模型相同率。默认模型仍为 DeepSeek，不设相同率阈值，不将单套相同率解释为准确率或全面等效。
