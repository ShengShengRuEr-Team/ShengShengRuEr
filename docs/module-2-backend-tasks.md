## T01 业务模型与 Alembic 迁移

- **对应需求**：M2-B08；验收 B02、B14、B15
- **依赖**：无
- **目标**：在不触碰模块一 4 张表的前提下，建齐开发文档第 3.2 节的模块二业务表与系统记录表。
- **改动范围**：`backend/app/db/models.py`（新增模型）、`backend/alembic/versions/0002_module2_listening_papers.py`（新增）、`backend/alembic/env.py`（确认模型已注册，通常无需改）
- **实现要点**：继承同一 `Base` 与 `NAMING_CONVENTION`；`down_revision="0001_initial_auth_only"`；约束命名用 `op.f()`；`is_current` 用部分唯一索引保证每套试卷至多一个当前批次；`upgrade()`/`downgrade()` 成对可回退。
- **验收标准**：
  - 空库执行 `alembic upgrade head` 成功，模块一 4 张表与数据不变；
  - `alembic downgrade 0001_initial_auth_only` 可回退且无残留；
  - 在**第二套**开发/测试库重跑迁移同样成功（B02 可复现）。
- **验证命令**：`python -m alembic upgrade head` → `python -m alembic downgrade 0001_initial_auth_only` → `python -m alembic upgrade head`；`python -m pytest -v`（B15 回归）。
- **交付物**：迁移文件、模型定义、迁移说明。
- **不做**：不建前端表、不建作答/判分表、不改动 `users/roles/user_roles/token_revocations`。

## T02 样例材料核对与结构化导入文件

- **对应需求**：需求 §3.3 第 1、2 条；验收 B03、B16
- **依赖**：可独立启动
- **目标**：固定 2025 年 6 月四级第一套完整听力样例，产出可核对、可追溯的结构化导入文件。
- **改动范围**：受控材料目录（**不进 Git**）、`backend/var/import/`（脱敏结构化文件，待确认是否入库）、`docs/requirements/` 内的核对记录（脱敏）
- **实现要点**：
  - 取回原卷 PDF、答案解析 PDF、原始 M4A、时间校对稿、旧采集表、`schema_options_merged_16tables.json`，逐文件记版本/哈希，形成来源清单；
  - 指定内容核对负责人（**待施博宇确认，本卡不填虚构人名**），逐题核对 25 题的题干、A–D、标准答案、解析、原文对应关系，核听整套约 23.6 分钟音频；
  - 每题一行记录核对人、日期、原卷/解析页码、问题、修正内容、复核结论；
  - 产出结构化文件：试卷、音频、8 篇章、165 片段、25 题、100 选项、25 条原卷映射、内容组，字段与迁移表一一对应；
  - 历史试填的自动转写、时间对齐与待审核标注**不得**直接标记为人工审核通过。
- **验收标准**：材料与来源清单固定；逐题核对与整套核听完成，附真实人员、范围、结果和修正记录（B16）；题号与选项顺序来自本套原卷映射，不默认恒等、不复用其他套卷答案字母（B03）。
- **验证命令**：逐题对照表人工签字/记录；`sha256sum` 或等价工具核对音频与清单一致。
- **交付物**：来源清单、结构化导入文件、内容核对记录、问题修正记录。
- **不做**：不做 OCR/ASR 自动识别，不生成技能与证据标注，不把本次整理说成模块三成果。

## T03 可重复执行的导入工具

- **对应需求**：M2-B07、M2-B08；验收 B02、B09、B13
- **依赖**：T01、T02
- **目标**：把结构化文件与真实音频写入 PostgreSQL，支持幂等、整体回滚与批次切换。
- **改动范围**：`backend/app/import_module2.py`（新增）、`backend/scripts/` 内运行说明、`.gitignore` 补充受控目录
- **实现要点**：
  - 命令 `python -m app.import_module2 --input <文件> --audio-dir <目录>`，输出导入摘要与校验结果；
  - 以来源清单 + 文件内容哈希计算 `batch_code`；同批次已 `active` 时直接返回「已导入，无变更」，不新增记录、不切换批次、不清除可见确认；
  - 新批次先写 `pending` 草稿，校验通过后在单事务内建记录、绑定音频、置 `active` 并切换 `is_current`；失败整体回滚；
  - 音频文件放受控目录，DB 存 `storage_key`、`file_hash`、`duration_ms`、绑定关系；导入时校验文件存在、可读、哈希与时长一致；
  - 字段缺失、外键错误、映射异常、文件缺失给出可定位信息；禁止占位答案/虚构解析/虚构原文；
  - 保留来源、批次标识与当前批次记录，一次整卷查询的题组、题目、音频引用属于同一批次。
- **验收标准**：同一材料重复导入无重复记录、不无故切换批次或清除已有可见确认（B13）；可控错误导入失败后不留下半套试卷、不污染当前数据，原当前批次及其可见状态保持有效（B09）；导入结果可在另一套库复现（B02）。
- **验证命令**：正常导入 → 重复导入比对记录数 → 故意破坏一条外键/删除音频后导入，检查回滚 → 切换新批次后检查旧可见确认不继承。
- **交付物**：导入工具、输入格式说明、运行方式、材料来源与校验结果说明。
- **不做**：不实现自动处理重跑或完整历史版本管理平台。

## T04 独立数据访问层与当前批次查询

- **对应需求**：需求 §5 第 3 条；M2-B01、M2-B07；验收 B02、B09、B14
- **依赖**：T01、T03
- **目标**：所有业务查询经独立数据访问层用 SQLAlchemy 执行，保证同一接口的数据与状态来自一致的当前批次。
- **改动范围**：`backend/app/repositories/`（新增，命名待确认）、`backend/app/db/` 内查询辅助
- **实现要点**：按当前批次取试卷、篇章、题目、原卷映射、音频引用；不混入草稿或失败批次、不叠加重复题目；管理员与学生分别组装返回结构，受限字段在服务端剔除；断库时抛出明确错误，不回退到写死样例。
- **验收标准**：接口查询结果与 `psql` 查库一致（B02）；学生查询不混入其他批次（B09）；断开数据库时明确报错（B14）。

- **交付物**：数据访问层代码与查询说明。
- **不做**：不在接口处理代码里写死整套题目，不建每张 16 表独立接口。

- **目标**：实现接口 1、2，按原卷顺序返回试卷信息、题组、题号、题干与选项。
- **改动范围**：`backend/app/api/listening_papers.py`（新增）、`backend/app/schemas.py`（新增响应模型）、`backend/app/main.py`（挂载 router）

- **不做**：不返回答案/解析/原文给学生，不做前端页面。

## T07 可见性、最低内容检查与操作记录

- **对应需求**：M2-B06、需求 §3.3 第 3、4 条；验收 B06、B08、B09
- **依赖**：T04、T03
- **目标**：实现接口 5 与检查逻辑，状态与操作记录持久保存。
- **改动范围**：`backend/app/api/admin_listening_papers.py`、`backend/app/services/visibility.py`（新增，命名待确认）、`backend/app/repositories/`
- **实现要点**：
  - 学生访问 = 当前批次 ∧ 最低内容检查通过 ∧ 管理员确认可见；
  - 检查覆盖完整题量、题序与选项映射、必要展示字段、音频可用性；未通过返回缺题/题序错误/选项映射异常/音频不可用等具体问题；
  - 确认可见与取消可见写入数据库并记 `visibility_audit_logs`；取消后列表不再返回该卷，详情与音频请求拒绝；**取消可见不以检查通过为前提**；
  - 新批次默认不可见，成为当前批次时不继承旧批次确认，须检查通过后重新确认；
  - 可见性、检查结果与操作记录持久保存，不联动修改标注审核或模块三验收状态。
- **验收标准**：确认与取消及记录持久保存，检查未通过时拒绝确认并说明原因但允许取消，取消后学生列表/详情/音频均拒绝（B08）；新批次不继承可见确认，导入失败不影响原当前批次（B09）。
- **验证命令**：确认 → 学生可见 → 取消 → 学生列表/详情/音频均拒绝 → **重启后端**再查仍有效；制造缺题/音频缺失后尝试确认 → 400 且含具体问题。
- **交付物**：可见性服务、检查逻辑、操作记录模型使用说明。
- **不做**：不实现模块三语义标注与证据自动检查引擎。

## T08 受控音频读取接口

- **对应需求**：M2-B05；验收 B07、B10
- **依赖**：T04、T05
- **目标**：实现接口 3，返回与试卷绑定的、实际可读取的样例音频。
- **改动范围**：`backend/app/api/listening_papers.py`、`backend/app/core/config.py`（音频目录配置项，待确认）
- **实现要点**：读取前复用身份与内容权限判断（与试卷访问条件一致）；按 `storage_key` 从受控目录读取，返回可解码音频流与正确 `Content-Type`；文件缺失、不可读或绑定错误返回明确结果；音频文件本体不入库。
- **验收标准**：可实际读取、解码并核听绑定正确的整套音频；学生不能绕过试卷权限读取音频（B07）；异常有明确响应（B10）。

- **不做**：不做浏览器播放器与暂停按钮（前端阶段），不做波形/逐句循环。
