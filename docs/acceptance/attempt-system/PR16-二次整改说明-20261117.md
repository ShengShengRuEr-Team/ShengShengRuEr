## 2. 问题与修复

### F08（P2）一致的“未提交”响应不能解除此前的冲突冻结

- **根因**：`queryStatus` 的手动 false 分支只处理 `answering && frozen && !conflict` 且不清除 conflict；pending 模式完全不进入解除路径，导致：
  - 普通草稿：页面提示“服务端尚无成功提交记录”，但选项仍为 0、交卷仍禁用；
  - pending：合法信封虽保留，但“重试提交（同键）”仍因 conflict 禁用。
- **修复**：重写手动 `not-submitted` 分支，统一按页面模式恢复：
  1. 统一 `setConflict(false)`、`setStatusUnknown(false)`；
  2. `answering`：`setFrozen(false)`，草稿答案保持，恢复可编辑/可交卷；
  3. `pending`：保留原 key/frozenPayload 与冻结答案，仅解除 conflict 禁用，允许保留期策略下的手动同键重试；
  4. `unrecoverable`：损坏信封仍按独立保护规则处理，不因 false 放开或清理；
  5. 其他终态：仅提示，不降级。
- **代码**：`frontend/src/pages/student/ListeningPaperPage.tsx`（`queryStatus` 的 `not-submitted` 手动分支）。
- **回归**：
  - 组件：`F08A 冲突后一致 false 解除普通草稿冻结并恢复可作答`、`F08B pending 冲突后一致 false 解除重试禁用且保留信封`；
  - 浏览器：E2E-15（`e2e-12-conflict-then-false-unfrozen.png`）、E2E-16（`e2e-13-pending-conflict-then-false-retry.png`）。

### F09（P2）手动查询收到 malformed 响应时仍可编辑、交卷

- **根因**：首次加载 malformed 已冻结，但手动查询只对 `status-conflict` 冻结；`status-unavailable/malformed` 落入通用错误分支，仅改 notice，页面保持可编辑。
- **修复**：手动查询的 `status-unavailable` 分支区分 `malformed`：
  - `malformed`：`setFrozen(true)`、`setStatusUnknown(true)`，提示“已冻结编辑，请重新查询提交状态”；
  - `not-accessible` / `server` / `network`：保持原降级策略（不改 editable 语义）。
  与首次加载的 AC-48 冻结口径一致，保留草稿/信封/标记，允许再次查询。
- **代码**：`frontend/src/pages/student/ListeningPaperPage.tsx`（`queryStatus` 的 `status-unavailable` 分支）。
- **回归**：
  - 组件：`F09 手动查询 malformed 必须冻结可编辑页面`；
  - 浏览器：E2E-17（`e2e-14-manual-malformed-frozen.png`）。
