## 五、问题清单（按严重程度）

### 1. [高] 新导入试卷在管理端无法“确认开放”，形成不可达闭环（F07 PARTIAL）

- **位置**：
  - `frontend/src/pages/admin/ListeningPaperDetailPage.tsx:149-155`：`!checkPassed` 即给出禁用原因；
  - `frontend/src/pages/admin/ListeningPaperDetailPage.tsx:262-268`：按钮 `disabled`；
  - `frontend/src/pages/admin/ListeningPaperDetailPage.tsx:217-223`：提示“本页只能读取检查记录”；
  - `backend/app/services/visibility.py:52-54`：确认动作本身才执行检查并写入 `content_checks`。
- **事实**：全仓库 `content_check.run_check` 仅由 `confirm_visible` 调用；导入工具 `backend/app/import_module2.py` 不生成检查记录。实测新导入卷为“尚未检查”，UI 确认键禁用，抽屉无重检入口 —— **UI 永远无法为一张新卷产生第一条“检查通过”记录**。本次截图中的 F07 通过状态，是先用 API 调 `POST /visibility`（confirm 再 cancel）预置检查记录后才可达。
- **复现**：用真实导入工具导入一套合法试卷 → 管理员打开详情 → “检查=尚未检查”，“确认开放”置灰 → 点“查看检查结果”，提示只能读记录。
- **最小修复**：允许“尚未检查”时点击确认（后端本就会执行检查，失败返回 400 与具体问题，前端失败后已重读检查记录，`DetailPage.tsx:173-182`），即从 `confirmDisabledReason` 去掉 `!checkPassed` 分支；或增加“执行检查”按钮调用检查服务。同时修正交接文 §六 D1“跑导入/检查工具”的表述（仓库内无该工具）。
