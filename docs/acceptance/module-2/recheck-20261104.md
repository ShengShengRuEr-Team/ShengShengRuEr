## F01：失败清理误删已有版本音频（P1）

**关联要求：§3.3.4、M2-B05、M2-B07.3/5、B07、B09、B13。**

原来“不同新音频导入失败，原文件不得被覆盖”的清单场景已经通过。但修复引入的版本文件路径没有被完整保护。

复现步骤：

1. 导入并开放原始真实试卷及音频 A。
2. 使用不同 `audio_code`、相同申报 `storage_key` 导入不同内容的音频 B。导入成功后系统生成 `<原文件名>-<hash8>.m4a`，切换新批次；管理员重新确认可见。
3. 再次导入引用音频 B 的不同材料，保留原申报 `storage_key`，仅将最后一题 `passage_src_id` 改成不存在的 `999`，触发数据库写入中途失败。此时不是相同材料的幂等重导。
4. 检查当前批次、数据库记录、实际文件及学生音频请求。

| 检查项 | 预期 | 本轮实际 |
| --- | --- | --- |
| 导入结果 | 失败 | `KeyError: 999` |
| 当前批次与业务行数 | 保持不变 | 保持不变 |
| 原可见状态 | 保持有效 | 数据库仍为 `true` |
| 已有版本音频 B | 文件与哈希保持不变 | **文件被删除** |
| 学生读取原当前批次音频 | 可正常读取 B | **404：音频文件不可用** |

本轮被误删文件：`CET4_2025_06_1_听力-74bca46c.m4a`；删除前 SHA-256 为 `74bca46c6b457ff3110852ebb49c0a572d0ca08830430eb9b1daa01409bc3b2a`。

原因：[_resolve_audio_target 第 113 行](../../../backend/app/import_module2.py#L113)在原请求文件存在但内容不同时，直接返回哈希后缀路径和 `needs_write=True`，没有检查这个后缀文件是否早已存在并被引用。[异常清理第 399 行](../../../backend/app/import_module2.py#L399)据此删除 `destination`；即使本次尚未执行文件替换，也会删掉已有文件。

修复要求：解析最终版本路径后再次判断是否可直接复用；独立记录本次操作实际新建或替换过哪些文件。失败时只清理本次拥有的临时或新建文件，不能依据“需要写入”标志删除可能已经存在的目标。复验须覆盖“已有后缀版本文件 + 中途失败”和“提交失败”场景。

具体输入与结果：`failed-reuse-of-resolved-version.json`（证据包）、`results.json`（证据包）。测试发现后仅恢复了隔离库对应的音频副本，以继续验证其他场景，没有修复开发代码。

## F02：首次导入仍能以缺题数据自证完整（P2）

**关联要求：M2-B02.1/3、M2-B06.4/5、B03、B08。**

已固定应有题量 25 后，再导入 24 题的新批次，会正确返回 400，问题中包含 `question_count_mismatch` 和 `question_no_not_sequential`。这一清单场景通过。

但对于首次导入，`expected_question_count` 仍是可省略字段。[导入代码第 242 行](../../../backend/app/import_module2.py#L242)在没有申报值时直接使用 `len(payload["questions"])`，缺题材料会成为自己的检查基准。

本轮使用另一套全新空 PostgreSQL，保留真实试卷编码 `CET4_2025_06_1`，从现有 25 题结构化材料中仅删除最后一题及其映射，不申报 `expected_question_count`。提供的原始结构化材料本来就没有这个新增字段。

| 检查 | 实际结果 |
| --- | --- |
| 选定原卷的题量 | 25 |
| 输入题目及映射 | 24 / 24 |
| 首次导入 | 成功 |
| 系统持久保存的应有题量 | **24** |
| 管理员确认可见 | **200** |
| 学生详情 | **200，返回 24 题** |

因此，F02 对已有可信题量的试卷有效，但没有完全堵住缺题开放。修复要求：应有题量来自固定原卷核对结果或可信材料清单，首次导入没有该依据时应拒绝开放或报告未建立完整性基准；不能从待校验题目数直接推导应有题量。升级迁移直接按当前题目数回填也不能独立证明旧样例完整，需保留来源核对依据。

证据：`fresh-count-result.json`（证据包）、`首次缺题输入`（证据包）。该场景是在全新数据库使用真实原卷编码验证，没有通过人为更改数据库的应有题量制造故障。
