## 2. API-3 契约定稿

- 路径/权限/响应头/字段与需求 §6.2、开发 §2.8 一致：学生本人；管理员 403；未登录 401；不可访问 404；成功与 404 均 `Cache-Control: no-store`。
- 成功 `msg="查询成功"`；错误沿用 API-1 的 `资源不存在`。
- `latest_attempt` 复用 API-1 `AttemptSubmitData`（含内层 `exam_paper_id`，必须与外壳一致）。
- 语义不变量：`submitted === (attempt_count > 0)`；`true` 允许 `latest=null`（仅汇总不可用）；`false` 必须 `count=0/latest=null`。

## 3. 与需求文字的实现差异（均已评审可接受）

| 项 | 需求/开发写法 | 实现 | 原因 |
| --- | --- | --- | --- |
| E04/E08/E09 HTTP 状态 | 文档只固定“明确失败”，未固定状态码 | 后端基线均为 **400**（E04/E05/E07/E08/E09），E03/E14 为 404 | 以基线 API-1 实现为准，不改契约；前端按真实 `status+msg` 匹配 |
| E03/E14 文案 | 文档示例“不可访问”类 | `资源不存在` | 基线统一文案，避免泄露存在性 |
| E05 识别 | “参数异常” | `缺少或非法的提交键 Idempotency-Key`（400） | 基线在解析 Header 时校验，缺失/非法均 400 |
| E09 false 处理 | “false 清后新键” | 查询 false 后清信封、回可作答；下次交卷生成新键 | 按需求 §2.10/附录 B；旧键作废、答案保留 |
| 交卷按钮数量 | 原型 P-02 线框在答题卡与底部各有一个 | 仅底部提交栏一个「交卷」；答题卡只显示计数 | 避免可访问名重复导致的误点击；功能位置/信息不变 |
| 练习估分 | max/label 固定口径 | 后端判分服务按原卷算；不可用时 `value=null` 并给 reason | 与 API-1 既有实现一致 |
| `submittedAt` | 可空 | E08/坏汇总/true+latest=null 写 `null`，页面不显示时间 | N03 |
| malformed 的页面处理 | 需求 §4.1 流程图残留“普通可答”，AC-48 要求“malformed 不放开作答” | 统一按 **AC-48 冻结编辑**；提供“查询提交状态”，服务端确认未提交后解除冻结 | 更具体的验收条款优先；PR16 F01b 回归覆盖 |
| 损坏信封与查询结果冲突 | §3.4/§8.6/AC-46 要求损坏信封受保护 | 损坏信封保护优先于 malformed/conflict/not-submitted/不可访问等查询结果（一致已提交除外） | PR16 F01 回归覆盖 |
