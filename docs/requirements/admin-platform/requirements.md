## 2. 公共接口、页面和权限规则

### 2.1 请求、结果与列表约束

1. 本期新增 JSON 接口均在 `/api/v1/admin/` 下，除 §9 的部署探针。普通结果沿用 `{code,msg,data}`，HTTP 状态与 `code` 一致；成功为 200。无凭证、过期、撤销、无效账号/会话为 401；已认证非管理员为 403；管理员查无对象为 404；字段格式错误为 422；状态冲突、重名、受保护操作和范围超限为 400；内部失败为 500。不得为本期改写原模块三接口状态码。
2. 数据库不可用导致无法完成鉴权时返回 500，不误报凭证失效或清除浏览器登录态；凭证确实失效的 401 才清理并跳登录。OpenAPI 成功结果为原始 schema JSON；CSV 为文件流，失败结果仍是上述 JSON；分别使用专用客户端通道。
3. 列表统一 `page=1`、`page_size=20`，允许 10/20/50/100，超限为 422；成功 `data={items,total,page,page_size}`。ID 为正整数。时间存 PostgreSQL `timestamptz`，JSON 用带时区 ISO 8601；界面按 `Asia/Shanghai` 展示并标明时区。
4. 时间筛选统一 `[start_at,end_at)`，两端需带时区，反向区间为 422。日志默认北京时间今天及前 6 天，单次最多 90 天；无填写时间时服务端也应用默认范围。新列表按时间降序、ID 降序稳定排序；支持的筛选见各功能，不开放任意字段排序/SQL 条件。
5. 请求追踪由服务端产生 `request_id`，返回响应头 `X-Request-ID`；传入文本不直接作为日志主键。写操作以一次请求内唯一 `event_id` 去重。异常不返回堆栈、连接串、文件绝对路径、密钥或令牌。
6. 所有新增用户输入字段白名单校验、长度限制；禁止额外字段静默写入。监控数据只读请求不触发业务写控制。写操作禁用重复点击；网络中断时显示结果未确认并刷新状态，不自动重放密码、启停、强退等操作。

### 2.2 固定角色与权限码（ADM-PERM01）

仅有 `admin`、`student`，沿用已有角色语义。管理员获得下表全部权限；学生对新增管理权限一律为空。前端从 `getInfo` 新增的 `permissions: string[]` 获取展示权限；旧字段不删除，既有页面不依赖此字段继续可用。后端对每个管理接口同时执行现有认证、管理员检查及对应权限码检查；隐藏按钮不能代替服务端鉴权。

| 权限码 | 覆盖动作 |
| --- | --- |
| `admin:user:read` | 用户列表/详情 |
| `admin:user:create`、`admin:user:update`、`admin:user:status`、`admin:user:resetPassword` | 创建、改昵称、启停、重置他人密码，分别校验 |
| `admin:self:read`、`admin:self:update`、`admin:self:password` | 管理员本人资料/改密 |
| `admin:session:read`、`admin:session:revoke` | 会话列表、强退 |
| `admin:log:read` | 两类日志列表/详情 |
| `admin:docs:read`、`admin:docs:debug` | schema 与文档、限定 GET 调试 |
| `admin:monitor:read` | 数据/服务/缓存/TLS/OAuth 状态 |
| `admin:job:read`、`admin:job:control` | 任务配置/记录、暂停恢复及立即执行 |
| `admin:cache:clear` | 当前实例白名单缓存清理 |
| `admin:dashboard:read` | 业务首页汇总 |
| `admin:export:users`、`admin:export:loginLogs`、`admin:export:operationLogs` | 三类导出，另需对应读取权限 |

映射以版本化后端常量为准，不新增权限配置表、角色分配页或通配符管理员绕过逻辑。验收需使用后端测试映射移除某个权限，证明直调受限接口为 403；这仅为测试配置，不增加面向用户的权限编辑功能。

## 3. 账户、会话与令牌生命周期

### 3.1 用户与管理员本人（ADM-USR01—03、ADM-SELF01—02）

| 项目 | 确定规则 |
| --- | --- |
| 用户列表 | `GET /admin/users`；筛选 `username`、`nickname`（包含匹配，最长 50 字）、`role`（admin/student）、`status`（active/disabled）。数据为 ID、用户名、昵称、角色、状态、创建/更新时间；详情 `GET /admin/users/{id}` 同范围，无密码、哈希、令牌、作答明细 |
| 新建 | `POST /admin/users`；字段 `username,password,nickname,role`；新建角色单选 admin/student，默认 student，状态 active。username 保留大小写且与现有登录精确匹配一致，去掉首尾空格后须符合 `[A-Za-z0-9_]{3,50}`；已有用户名不在本次批量重命名或转小写。重复名为 400，唯一约束兜底，不生成两个账号 |
| 密码约束 | 新建、重置、新改密码统一 10—64 个字符，UTF-8 编码不超过 72 字节，至少含一个 ASCII 字母和一个数字；不做 trim，允许空格/符号但仍受长度规则限制；不得等于用户名或当前密码。沿用 bcrypt，既有旧密码仍可用于原登录和旧密码验证，不因新设置规则强制废弃历史账号 |
| 修改昵称 | `PATCH /admin/users/{id}`，仅 `nickname`，0—50 字符；去掉首尾空格，空串允许；用户名与已有角色只读，不提供删除接口 |
| 启停 | `POST /admin/users/{id}/status`，`status` 加 1—200 字理由；禁止停用本人，禁止将最后一个 active 管理员变为 disabled。并发修改以数据库事务串行化该保护判断，不得先查后无锁更新；重复设置同状态返回成功 `changed=false`，不重复增加认证版本 |
| 重置他人密码 | `POST /admin/users/{id}/reset-password`，`new_password` 与 1—200 字理由；禁止通过此接口重置本人，提示使用个人中心；可重置停用账号但保持 disabled。成功不回显密码，管理员自行输入后由既有线下渠道交付，系统不自动发消息 |
| 本人资料 | `GET /admin/me`、`PATCH /admin/me`；只修改 nickname；头像、电话、邮箱、部门、岗位不纳入本期 |
| 本人改密 | `POST /admin/me/password`，`old_password,new_password`；旧密码错误为 400；成功后撤销本人所有会话并退出，必须重新登录，不签发替代令牌 |

### 3.2 数据与并发保证

`users` 新增 `auth_version`（整数，默认 0）。新增 `auth_sessions`：不含完整 JWT；保存会话 UUID、用户 ID、jti 的 SHA-256 指纹、签发认证版本、签发/到期/末次有效活动时间、撤销时间/原因、IP 与截断至 256 字的 UA。jti 指纹唯一且不可逆展示；对外仅给会话 UUID。原 `token_revocations` 保留，正常退出继续兼容原撤销机制。

新登录 JWT 增加认证版本，登录会话登记和成功登录日志同一数据库事务提交后才返回 token。后续受保护请求需同时满足签名/时效、原撤销检查、账号 active、版本一致、会话存在且未撤销。失败顺序仍为 401 → 角色/权限 403 → 对象 404。

认证成功时以一致的账号锁顺序协调登录、停用、改密、强退；安全操作提交后发起的新请求必须拒绝旧会话。已通过认证并开始执行的在途请求允许按原业务事务结束，不承诺追回已返回内容。本期部署切换为新会话模型时，缺少登记/版本的历史 JWT 统一返回 401，要求重新登录；在发布说明写明该一次性兼容行为，不伪造旧会话回填。

### 3.3 状态转移表

| 操作 | 账号/凭证状态 | 操作前的令牌结果 | 操作后的会话结果 |
| --- | --- | --- | --- |
| 新登录 | active，版本不变 | 不影响其他有效会话 | 新增一份会话；有效期沿用现有配置（基线 120 分钟），不滑动续签 |
| 正常退出 | 不改账号/版本 | 当前 jti 撤销 | 当前会话关闭；其他设备继续有效；已撤销令牌后续请求 401 |
| 停用账号 | active → disabled，版本加 1 | 全部旧令牌失效 | 全部未关闭会话记 account_disabled；不能新登录 |
| 重新启用 | disabled → active，版本不减 | 停用前旧令牌仍 401 | 必须使用当前密码重新登录 |
| 本人改密 | 密码更新，版本加 1 | 本人全部旧令牌失效 | 全部会话记 password_changed；成功响应后本页面退出 |
| 重置他人密码 | 密码更新，版本加 1；保留原账号状态 | 目标全部旧令牌失效 | 目标会话记 password_reset；不影响操作者会话 |
| 单会话强退 | 不改密码/账号版本 | 仅目标会话令牌失效 | 目标记 kicked；同账号其他设备不受影响 |
| 自然到期 | 不改密码/版本 | 到期令牌 401 | 不计在线；按到期时间参与留存清理 |

启停、改密、重置、强退、角色读取及会话状态需跨 API 进程共享 PostgreSQL 事实，不能只维护内存列表。不得删除 users 或历史作答；管理端仍不能读取个人结果。凭证变化失败必须回滚密码/状态/版本/会话和成功审计，不留半成功状态。

### 3.4 在线观察与单会话强退（ADM-MON01）

`GET /admin/monitor/sessions` 支持用户名、固定角色筛选，展示当前未撤销且未到期、账号 active、认证版本一致，且 `last_activity_at > server_now-5分钟` 的会话。等于窗口边界即不在线；返回 `as_of,active_account_count,active_session_count` 及分页项。

活动来源仅包括登录成功、正常受保护业务调用和用户主动触发的新增管理操作；模块三既有业务请求只在共享认证层观察，不改其处理结果。自动轮询的全部 `/admin/monitor/*`、首页汇总、日志/列表自动刷新、schema 和部署探针不更新活动时间；用户打开页面后的定时刷新不能永久保持在线。普通请求的会话活动写入每会话最多每 30 秒一次，窗口精度误差允许 30 秒；登录时间立即写入。浏览器关闭无即时事件，最多 5 分钟加上述误差后消失。

列表字段：会话 UUID、用户 ID/名、角色、IP、UA 摘要、登录/末次活动/到期时间、是否当前会话。不展示原始 jti、令牌、请求正文。

`POST /admin/monitor/sessions/{session_id}/revoke`：1—200 字理由，确认后只强退该会话；已关闭会话返回 200 `changed=false`。允许强退自己的其他会话；禁止强退当前会话，提示使用正常退出。没有全账号强退按钮，账号级撤销由停用/改密承担。操作后新发起的受保护请求 401，不要求切断已经开始传输的响应。

## 4. 登录与管理操作日志

### 4.1 事件与字段（ADM-LOG01、ADM-LOG02）

| 事件 | 主体、记录时点和结果 |
| --- | --- |
| LOGIN_SUCCEEDED | 认证账号 ID、快照角色；会话登记与登录日志提交后记成功并发 token。为准确识别在线会话，既有 admin/student 登录都登记，只有管理员可以查日志 |
| LOGIN_FAILED | 账号可为空；账号不存在仅记录客户端声明用户名（最多 50 字），失败类型 UNKNOWN_ACCOUNT/BAD_PASSWORD/DISABLED；对外仍统一“用户名或密码错误”，内部类型不回显 |
| LOGOUT | 当前用户/会话，撤销事务提交时记成功；401 的过期或已撤销请求不伪造正常退出 |
| USER_CREATED/PROFILE_UPDATED/USER_STATUS_CHANGED | 操作者、目标用户、允许字段的变更摘要和理由；不含密码或角色授权表达式 |
| PASSWORD_RESET/SELF_PASSWORD_CHANGED | 操作者、目标用户、失效会话数与结果；不含旧/新密码、密码哈希 |
| SESSION_REVOKED | 操作者、目标会话 UUID、目标用户、理由与 changed |
| JOB_PAUSED/JOB_RESUMED/JOB_TRIGGERED/JOB_FINISHED | 操作者或 system、job_id、run_id、执行结果/数量；触发接受与执行完成是不同事件 |
| CACHE_CLEAR_STARTED/CACHE_CLEARED | 操作者、白名单域、instance_id、条目数与结果；前者只表示清理意图已持久化，后者才表示清理动作完成 |
| EXPORT_COMPLETED/EXPORT_FAILED | 操作者、导出类型、已脱敏筛选摘要、行数、结果；见 §10 的文件传输定义 |
| DOC_GET_DEBUG | 管理员在文档页显式执行的白名单 GET，记录路由模板、耗时、结果；不记录实际 URL 中的秘密、响应正文 |

新增 `admin_login_events`、`admin_audit_events`，至少含事件 UUID、`request_id`、类型、主体用户 ID 可空、主体显示快照、目标类型/ID可空、结果 SUCCESS/FAILURE、原因码、已脱敏摘要、IP、UA、`duration_ms`、UTC 时间；操作日志可含 `run_id`。事件 UUID 唯一。用户名、理由和摘要作为数据转义展示，不渲染 HTML。

通用日志不替代 `visibility_audit_logs` 或模块三审计。本期不扩展模块三业务日志钩子；现有发布/可见性记录仍归原业务，日志页可提示原记录入口但不得伪造字段级修改记录。普通运行堆栈留在运行日志，不作为管理端详情全文展示。

### 4.2 事务与日志故障策略

1. 本期数据库关键写操作的成功审计与用户/会话/任务配置等变更同事务提交；审计写入失败则事务回滚，返回 500，不返回虚假成功。日志存储失败时，成功登录不签发 token。本地缓存清理和分批留存作业分别按 §6.4、§7 的非原子操作边界执行，不能声称它们能随一个数据库事务全部回滚。
2. 业务失败先回滚，再用独立 Session 记录失败审计；原失败仍按 400/422/404/500 返回。失败审计不因原业务回滚消失。认证失败事件没有已认证用户也可入库。
3. 数据库断开或失败日志也写入失败时，写仅含允许字段的结构化本地降级记录；仍返回原错误，不把失败变为成功。每实例运行目录 `var/admin-audit-fallback/`，10 MiB 单文件、10 份滚动，总上限 100 MiB；部署必须挂载持久卷，文件对外不可下载；不允许该清理任务把它当模块三目录扫描。写盘也失败时仅发 stderr 的固定错误码和 request_id，健康状态标 degraded，不声称有持久证据。
4. 降级文件由运维排障，**本期不做自动回灌**，不把未回灌文件行计作数据库日志。监控显示最近一次失败及待人工处置；文件轮转导致旧记录淘汰属于已说明的容量边界。
5. 同一次业务动作由其业务事务服务唯一负责记成功/失败；异常处理器只补无归属的系统异常，不重复生成相同事件。客户端重试属于新请求，状态幂等但可分别留下 changed=false 的记录。
6. 禁止记录密码、bcrypt 哈希、Authorization、完整 JWT、API 密钥、连接串、学生答案/成绩明细、材料正文和原始请求/响应体。IP 来源只信任已配置的反向代理，否则使用 TCP 对端。UA 最长 256 字，摘要最长 2 KiB。

### 4.3 查询、详情和留存

`GET /admin/logs/login`、`GET /admin/logs/login/{event_id}`，筛选声明用户名/结果/失败类型/IP/时间；`GET /admin/logs/operation`、`GET /admin/logs/operation/{event_id}`，筛选操作者用户名/事件类型/结果/目标类型/时间。过滤长度、分页和范围按 §2。不存在返回 404。未知账号不自动创建用户。

登录日志保留 90 天，管理操作日志保留 180 天；由 §7 的白名单任务清理。本期没有手动删日志或清空按钮；详情和导出遵循同一字段白名单。过期但尚未执行清理的记录仍可按范围查询，页面说明截止日期，不能假称数据已删除。

## 6. 运行监控能力与故障规则

### 6.1 通用状态、采集与新鲜度

每个指标独立返回 `value,unit,observed_at,source,scope,status,reason`。status 固定为 `ok/error/unknown/stale/not_configured/not_applicable`；value 可以为 null；阈值告警级别另用 `severity=normal/warning/critical/none`，不混淆采集成功与业务健康。

本期采样与前端刷新均为 15 秒；页面不可见时停止轮询，恢复可见立即查询；浏览器页面不是后台采集触发器。采集读数据库连接/查询最多 2 秒，单采样周期最多 5 秒；同实例相同采样不并发重复执行。距最近成功采样严格超过 60 秒为 stale，保留旧值与旧时间；新采集出错立刻显示 error 和最后成功值，不能把失败时间当 observed_at。配置明确未启用时为 not_configured，能力不适用时为 not_applicable，不伪造零。

监控 API 返回200表示成功取得状态包，包内可有 error；若认证、传输或整个聚合服务失败，仍返回真实 HTTP 错误，界面显示无法获取并标记旧数据。所有包含 `instance_id`（每次进程启动生成）、`booted_at`、`server_time`，进程池/本地缓存只代表当前实例，不相加冒充全群集。查询慢日志与告警推送不在本期。

### 6.2 数据监控（ADM-MON03）

接口 `GET /admin/monitor/database`。数据库名使用部署显示别名，不返回连接串、数据库账号、远端地址或 SQL 原文。应用只观察本业务数据库，不申请超级用户权限、不默认授予 `pg_read_all_stats`。

| 指标 | 对象、来源、单位 | 本期状态/阈值 |
| --- | --- | --- |
| connection_available | 配置业务数据库，独立受控 SELECT 1，布尔 | 2 秒内成功 ok；失败 error；不得回退静态样例 |
| probe_latency_ms | 上述一次探针单调时钟耗时，毫秒 | >500 warning，>1500 critical；明确仅为探针耗时，不称全库查询平均耗时 |
| database_size_bytes | 当前数据库 `pg_database_size(current_database())`，字节 | 不足权限为 unknown/permission_denied；不提升账号权限填数 |
| active_connections/total_connections | `pg_stat_activity` 按当前数据库聚合且调用者可见的连接数量，个 | 响应标 `visibility=role_visible`；明确可能不是全库完整统计，不能用其与 max_connections 比值报警 |
| checked_out/pool_size/overflow | 当前 API 实例 SQLAlchemy QueuePool 状态，个 | checked_out 达配置容量 80% warning、100% critical；非 QueuePool 时 not_applicable，不转换为全库连接数 |

来源及权限依据：[PostgreSQL 18 统计视图](https://www.postgresql.org/docs/18/monitoring-stats.html)。无权限、断库、查询超时分别给固定 reason。鉴权依赖同一数据库，断库时新管理请求可能整体500；前端保留旧数据并提示，独立探针按 §9 反映未就绪，不承诺断库后仍可私有查询完整统计。

### 6.4 缓存监控和列表（ADM-MON05、ADM-MON06）

本期新增且只管理一个实际缓存域 `admin_dashboard_summary`：每 API 实例内存保存 §10 首页汇总，唯一键 `overview`，TTL 15 秒，最多 1 项。缓存不含个人信息、schema、凭证、材料或任务结果；鉴权不缓存。配置缓存 `get_settings()`、模块三阶段产物与 Redis 都不属于此管理域。

`GET /admin/monitor/cache` 返回域名、instance_id、enabled、当前未过期条目数、TTL、进程启动以来命中/未命中次数；`GET /admin/monitor/cache/entries` 返回键名、创建/到期时间和剩余秒数，绝不返回缓存值。缓存关闭时明确 not_configured，Redis 独立行固定 not_configured，不能显示“Redis 使用0”。

`POST /admin/monitor/cache/clear` 输入 `domain=admin_dashboard_summary,expected_instance_id,reason`（理由1—200字）。只清当前响应实例的这个域；实例不符400，刷新列表重新确认，不能悄悄清另一实例；无条目返回200 `deleted_count=0`。界面先显示对象和最多1项预览，再确认；后端同样检查白名单。

执行顺序固定为：独立提交 CACHE_CLEAR_STARTED 意图事件 → 删除本地白名单缓存 → 独立提交 CACHE_CLEARED 结果事件 → 返回结果。开始事件写入失败则不清理并500；清理动作失败写失败结果并500；动作已完成但结果审计失败时缓存可能已清，写降级记录、返回500并提示“结果记录失败，请刷新确认”，不得宣称已回滚缓存。只看到 STARTED 不能当作完成；进程崩溃后缓存本身可重建，不恢复旧值、不伪造完成事件。此为本地非持久操作的明确边界，不声称与数据库原子提交。新汇总下一次读取重建；所有其他域或路径输入400，不存在任意文件/键删除能力。

### 6.5 传输加密及 OAuth 状态（ADM-MON07、ADM-MON08）

`GET /admin/monitor/transport` 只读返回 `direct_scheme,external_tls_state,configured_public_origin,source,reason`。部署用 `.env` 的 `PUBLIC_ORIGIN` 配置站点源，不接受客户端指定。直接TLS监听可据 ASGI server scheme 确认；代理终止TLS时只接受显式 CIDR 白名单中的 TCP 对端送来的标准 Forwarded/X-Forwarded-Proto，并要求与 PUBLIC_ORIGIN 一致；非可信代理头忽略。只有静态 https 配置而无可信运行证据时显示 unknown（已声明、未验证），本地 http 显示 not_configured（开发未启用TLS），不能显示已加密。链路两跳分别表达，不把上游TLS当后端也TLS；证书到期探测不在本期，不返回私钥或证书秘密。

`GET /admin/monitor/oauth` 返回 `status=not_configured,enabled=false,reason=oauth_server_not_deployed,events=[]`。页面说明“当前使用 JWT Bearer 登录，未部署 OAuth/OIDC 授权服务”，提供管理员可点击的登录日志入口；不做搜索出假事件，不把空数组当作“已启用但暂无审计”。本期无 OAuth 登录、客户端注册、授权码或令牌交换接口。

## 7. 定时任务及留存清理（ADM-MON02）

### 7.1 唯一注册任务

本期只注册 `admin.retention_cleanup`。调度为 `Asia/Shanghai` 每天03:10；任务处理范围仅：登录日志超过90天、操作日志超过180天、`admin_job_runs` 超过180天、已到期/撤销会话超过7天、过期 `token_revocations`。删除界限严格 `< cutoff`，相等保留；会话留存从 `max(expires_at,revoked_at或expires_at)` 算，active未到期不可删。当前这次清理的 run、触发/完成审计不被本次删除。

清理不扫描音频、原件、模块三表/目录、学生作答表、用户表、角色表、本地降级文件，不产生任何 OCR/ASR/模型调用。没有任意 cron、SQL、shell、Python表达式、用户脚本或通用任务新增编辑界面。

### 7.2 执行机制与页面

新增独立的管理端调度进程（Python入口由开发设计命名，独立于 API 和模块三 Worker），每15秒向 `admin_job_scheduler_state` 写自身心跳并检查到期任务。`admin_job_definitions` 记录 enabled、下次计划和最近执行；`admin_job_runs` 记录 run UUID、job_id、scheduled/manual、slot_key、发起人、开始/结束、状态、分表删除数量和脱敏错误。作业默认启用；调度进程启动失败不阻止 API 启动，但监控必须提示未运行。

同一任务用 PostgreSQL 会话级 advisory lock 互斥，并在独占专用连接持锁，整个作业不切连接；无锁返回手动400 job_running、自动跳过。连接丢失则停止后续批次、将未完 run 留作恢复处理，不能认为锁仍持有。每批最多1000行且独立提交，单次最多60秒或累计50000行；达到上限记录 PARTIAL，下次从剩余过期行继续。中途失败保留已完成批次并记 FAILED 与数量，不能声称整次清理已回滚。

计划 `slot_key` 以计划北京时间日期唯一，自动重试不新建同slot的另一份成功执行。重启后对最近24小时内错过的最近一个计划补跑一次，更早的记错过数量不逐次补跑；暂停时不积累补跑，恢复从下一个03:10开始。数据库失联重连后同规则。失败同run最多再试一次，间隔60秒；PARTIAL不自动立刻重试；成功/失败/部分均保存结束记录，人工可再触发。

未完成run超过120秒且重新获得互斥锁时，先标记 INTERRUPTED，再按该run剩余重试次数恢复；心跳不能冒充作业互斥证据。清理天然按过期条件幂等，崩溃在批次提交后的未计数部分标 `counts_complete=false`，不编造精确删除总数。

### 7.3 接口、控制与审计

- `GET /admin/monitor/jobs`：仅此任务的 enabled、固定计划、上次/下次执行和调度心跳；`GET /admin/monitor/jobs/{job_id}/runs`：分页执行记录；没有其他注册项时404。
- `POST /admin/monitor/jobs/{job_id}/enabled`：enabled加理由；暂停/恢复不取消已运行作业，页面明确显示。变更与成功审计同事务。
- `POST /admin/monitor/jobs/{job_id}/run`：理由，生成单次run并返回200 `{run_id,state:'QUEUED'}`，不把接受当执行完成；即使计划暂停也允许显式手动运行。只有调度进程执行，不在 HTTP handler 启动线程执行；心跳过期时400 scheduler_unavailable，不接受永远无人执行的队列。
- queued/running同任务只能一份，事务内锁定任务行并检查；并发重复触发只接受一份，其余400。非白名单任务400；未授权403。任务取得锁前再次验证run与审计记录，不能绕过排队去调用模块三 Worker。
- 作业开始前独立写运行记录，失败审计按 §4；日志/运行记录无法持久化时不得开始删除。完成记录失败时清理不能继续，降级到运行故障并按中断规则恢复。

### 10.2 CSV列表导出（ADM-EXP01）

本期仅提供以下三类同步CSV，均使用各自列表相同筛选、时区、排序和权限，忽略当前page导出全部匹配行，最多5000行且最多5MiB；读取快照/生成文件合计最多15秒。超行/超字节为400提示缩小范围，超时500，不截断后冒充完整导出。没有数据时返回只有表头的有效CSV。

| 接口 | 固定导出字段 |
| --- | --- |
| `GET /admin/exports/users` | 用户ID、用户名、昵称、角色、状态、创建时间、更新时间 |
| `GET /admin/exports/login-logs` | 事件ID、时间、声明用户名、已识别用户ID可空、角色快照可空、成功/失败、失败原因码、IP、UA摘要 |
| `GET /admin/exports/operation-logs` | 事件ID、时间、操作者名称/ID、事件类型、目标类型/ID、结果、原因码、脱敏摘要、请求ID、run_id可空 |

UTF-8 BOM、逗号分隔、CRLF、标准引号转义；时间显式 `+08:00`。任何文本单元格去除前导空白后以 `=,+,-,@` 开头，或原值以制表/回车/换行开头，写CSV时前置单引号防公式执行，不改数据库原值。文件名由服务端固定类型加北京时间组成，不使用用户输入路径。

文件在内存生成、计数和成功审计持久化后才返回 `text/csv` 与附件头、`Cache-Control:no-store`；无令牌/学生分别401/403且不返回文件。成功事件定义为“服务器完成生成并交付HTTP响应”，不声称客户端保存成功；原事件名 `EXPORT_COMPLETED` 采用此定义，客户端断开只在运行日志补传输中断，不伪造下载完成。审计写入失败时500且不交付CSV；生成失败记录EXPORT_FAILED。页面用专用文件通道解析失败JSON，不能把错误JSON保存成CSV。

无会话列表、缓存内容、个人作答或模块三材料/产物导出接口。导出不写临时文件，不新增导出调度平台，也不为本期加入通用导入。

### 12.2 最终复验门槛

1. 21项需求均有实现或指定的能力状态页，AC-01—AC-36逐项留证；OAuth未启用状态、Worker独立存活unknown是本期明确交付边界，不临时用来替代承诺过的能力。
2. 每次证据固定提交SHA、工作区状态、迁移head、配置摘要（脱敏）及新增依赖锁定版本；模块三可选观察开关明确记录。数据库与时钟测试使用独立测试环境和合成账号/数据。
3. 构建执行目标工程现有前端typecheck/build及后端受影响测试；对密码/会话、审计事务、双实例调度、私有schema、真实指标及权限边界增加有业务意义的检查，不只验证页面存在。
4. 文档复验只检查规则与映射，不需为“已写清需求”先跑软件测试；本期软件最终验收则必须运行上述实际场景。两类结果分开记录。
