## 一、目标与范围

### 1.1 模块目标

以试卷、答案解析、听力等原始材料为输入，自动完成题目提取、字段整理、题目与技能等关联标注，并按现有 16 张采集与标注表的业务结构实际写入 PostgreSQL。

管理员须能通过后端接口登记或选择材料、启动处理任务，查询任务状态、处理结果和异常。后台独立进程执行处理，入库结果须能被模块二现有接口读取，返回同一套试卷的完整听力部分及按权限开放的配套内容。独立运行工具可用于处理执行、校正、重跑及验收辅助，不开发操作页面。

### 1.2 一期范围

- 以一套材料完整、版式固定的听力样例验证端到端链路；同套文本 PDF 与扫描 PDF／图片两类输入均须实际处理并纳入验收，不扩展为任意扫描版式通用。
- “整套试卷”“整卷”均仅指某套四六级试卷的完整听力部分，不含阅读、写作和翻译。
- 自动化覆盖原始材料到题目、关联标注及数据库记录的全过程；允许对识别异常和关联疑点进行人工复核修正。
- 必须分别保留系统自动初稿与人工复核后的结果。
- 采用模块二的 2025 年 6 月四级第一套作为本轮样例，准备同套文本与扫描两类文档输入，绑定同一对应音频。已有导入与历史验证记录为 25 题、8 篇章、165 片段；这些是该样例记录，不是所有试卷的硬编码数量或本轮句级切分目标。采用前须完成原始材料与内容核查，历史待复核标注不能直接作为标准结果。
- 不因样例验收通过而承诺四级、六级及全部扫描格式均可通用。

### 1.3 不纳入一期的功能

学生作答、提交答案、判分、成绩、错题及个人作答记录，个人诊断、用户画像、RAG、推荐算法、DKT、学习路径等留待后续阶段。

本期不建设题库字段与标注的在线编辑器，不追加复杂批量审核、发布撤回、完整任务调度平台或复杂进度面板。人工复核通过校正文件或处理工具完成，再重新导入。

本轮不开发任何前端页面、组件、路由、材料选择界面、任务面板、题库展示页面或浏览器播放器，不以模块二业务前端完成为交付前提。前端未来接入可复用本轮后端接口，其实现不计入本次交付。

## 二、技术基础与模块接口边界

| 项目 | 要求 |
|---|---|
| 前端 | 本轮不开发，不要求修改现有前端工程 |
| 后端 | 复用 `backend/app` 的最小 FastAPI 工程、统一响应、鉴权及配置；原稿中的 RuoYi-FastAPI 是历史选型，不代表当前已集成其菜单、代码生成或 Redis 能力 |
| 数据库访问 | 复用现有 PostgreSQL＋SQLAlchemy、`Base`、数据库会话和 Alembic 增量迁移 |
| 处理执行 | 后端接口创建任务，后台独立进程执行长时间处理；可保留独立运行工具 |
| 数据结构 | 现有 16 表业务结构，另设必要的任务、批次、来源及版本记录 |
| 与模块一衔接 | 复用管理员身份与权限；任务启动及结果管理接口仅授权管理员 |
| 与模块二衔接 | 提供可实际查询的试卷、题目、关联及媒体数据，由现有题库接口读取验证 |

任务创建请求无需等待整套识别完成。OCR、ASR 和模型调用须与普通业务接口请求分开执行。

不得为模块三重建登录系统，或清空、重建 `users`、`roles`、`user_roles`、`token_revocations`。新增表沿用仓库命名和约束规范：表名复数 `snake_case`，主键 `id`，外键 `<实体>_id`，数据库时间使用带时区时间并按 UTC 保存。

现有后端环境与依赖锁定见 `backend/requirements.txt`，不能仅按旧调研另选版本。识别与模型环境须单独验证兼容性，可与 API 服务分开管理依赖。Redis、Celery 等尚不是当前模块二运行前提，不因原稿列出而强制引入。

### 2.2 现有题库接口的接入约束

下列接口已有实现，模块三结果须能被它们按原有权限消费，不另建一套重复题库查询接口。

| 方法与路径 | 现有用途与复用要求 |
|---|---|
| `GET /api/v1/listening-papers` | 管理员查询全部试卷；学生只获取可访问试卷 |
| `GET /api/v1/listening-papers/{exam_paper_id}` | 学生视角整卷详情，按篇章和原卷映射组装；当前实现对该详情使用可见性判定，管理员核对未开放内容使用配套接口 |
| `GET /api/v1/listening-papers/{exam_paper_id}/audio` | 受控音频流，支持 `Range`；访问时须携带认证信息并满足对应内容权限 |
| `GET /api/v1/admin/listening-papers/{exam_paper_id}/companion` | 管理员查询当前批次题目、答案、解析、原文和状态，不能替代历史批次及任务结果查询 |
| `GET /api/v1/admin/listening-papers/{exam_paper_id}/checks` | 返回当前批次已保存的最新最低内容检查结果；当前接口本身不执行一次新检查 |

音频通过带认证信息的 HTTP 请求验证实际文件流、`Range`、访问权限及可解码性，不要求浏览器播放或暂停按钮。不得为便于核验而直接开放媒体目录绕过鉴权。

## 三、输入、输出与来源要求

### 3.1 输入材料

| 输入 | 要求 |
|---|---|
| 试卷 PDF 或图片 | 同套文本 PDF 与扫描 PDF／图片均纳入固定版式验收，保存原件、输入类型和来源；若扫描件由原 PDF 转为图片生成，须标明派生方式，不将其描述为真实纸张扫描，验收结论仅覆盖实际测试的清晰度和版式 |
| 标准答案与解析文件 | 来源明确、可追溯；验收材料必须包含解析 |
| 对应听力音频 | 与试卷正确绑定，保存文件、哈希、时长及音频版本 |
| 原文及题干材料 | 默认从答案解析或可靠原文提取并核对；已有完整原文不运行ASR。缺少先待补充，明确选择无原文模式后才识别音频并另行核对 |
| 既有词典与结构 | 使用最新已确认的字段结构、技能／错因／体裁定义及编号、适用边界和使用范围；每次任务固定文件快照与哈希，不在任务中途自动跟随更新，当前可核实基线见 10.4 |
| 试卷元数据 | 管理员确认考试级别、年份、月份、套别及材料对应关系 |
| 完整性基准 | 从原卷核对得到的应有题量及其文件、SHA-256、定位说明；不能从本次识别出的题数反推 |

标准答案和解析不能靠音频识别或模型猜测补出。缺解析的题目须暂停完成状态，补齐后再验收，不得用占位文字冒充解析。材料缺失或绑定冲突时，进入待补充确认。

模块二现有样例的 `explanation_text` 含对来源解析的摘要改写；若沿用或继续生成摘要，须保留原始解析、定位和变换来源，并核对是否忠实于原意，不能表述为原解析逐字提取。

### 3.2 输出成果

核心输出是 PostgreSQL 中实际保存的试卷、音频、篇章、正文和问题片段、题目、证据及关联数据，并附任务状态、处理结果和异常信息。

原件及中间文件存入受控目录，数据库保存路径、哈希和引用。JSON、Excel 等中间文件可用于核对、导出和追溯，不能替代实际入库成果。音频须可由受控媒体接口实际读取，不能只保存无法访问的路径。

## 四、任务接口、运行工具与权限需求

### 4.1 必交功能

1. 管理员通过后端接口登记材料或引用已登记的试卷、答案解析和听力文件，并确认所属试卷。文件可由上传接口接收，也可由受控目录登记；具体方式在开发文档中冻结，不要求上传页面。
2. 调用任务启动接口后，后端创建任务并返回任务编号。
3. 后台独立进程执行提取、对齐、标注、检查及入库。
4. 管理员可通过接口查询任务状态、处理结果和异常，包括自动初稿、复核结果与差异。

最低交付包括材料登记与引用能力、仅管理员可调用的任务启动接口、任务状态及结果查询接口和独立处理进程。验收可使用 HTTP 客户端、接口文档中的交互测试或脚本完成，不要求自建页面。命令行工具可作为辅助入口，但不能替代必交接口及其权限核查；本机工具通过受控运行环境调用，不对学生开放。

材料登记、任务启动及结果查询是模块三增量；独立开发目录已实现部分接口，集成及完整验收状态另报。本期入口采用受控目录登记，不要求上传页面。任务结果须关联任务编号、试卷及批次；异常至少能定位处理步骤、来源文件或题目/片段、失败或待确认原因及受影响内容。

### 4.2 任务状态与可见性

任务状态至少区分：**待处理、处理中、处理失败、待确认、处理完成**。任务“处理完成”仍须按整套验收条件判断是否通过验收。

当前 `import_batches.status` 仅有 `pending/active/failed`，表示导入批次状态，不能直接拿来承担上述完整任务生命周期。新增任务记录须与导入批次关联；`active` 不等于标注已审核或模块三验收通过，失败任务即使没有成功写入业务批次，也须保留可查询的失败记录。

管理员接口可查询全部处理批次、结果和异常。学生无权启动处理任务；标准答案、解析、听力原文仅管理员可访问，学生接口及原始资料下载均不得提供这些内容。录音问题对应的题干仍属于学生接口可返回的题干。

管理员须能通过既有可见性接口确认或取消试卷对学生开放。学生接口仅读取当前批次中通过最低内容检查且经管理员确认可见的试卷。本文“学生可见”均指学生角色的接口访问资格，不要求开发学生页面。试卷可见性与模块三整体验收分别记录。

沿用模块二已确认规则：所有管理员可管理全部题库，不增加“只能查看本人导入试卷”的归属限制；新批次默认不可见，成为当前批次后须重新确认；取消可见不以检查通过为前提，取消后学生的后续列表、详情与音频请求均不得访问。已返回客户端的数据不属于服务端可追回范围。

## 五、自动处理流程与处理规则

**登记同套材料与可信题量 → 文本提取/OCR → 核对答案正文、提问、选项和解析 → 固定分句/题号/来源 → 音频规范化与粗定位 → 按原文逐句强制对齐 → 停下供用户核听确认 → 题目组装 → DeepSeek技能与证据候选标注 → 本地检查及待审入库 → 内容与标注复核 → 管理员确认切换当前批次 → 独立确认学生可见 → 模块二接口读取。**

| 步骤 | 处理要求 | 产出及异常处理 |
|---|---|---|
| 1. 材料登记 | 保存同套原卷、答案解析、音频的哈希、类别及来源；从原卷独立核对应有题量 | 缺材料或绑定冲突时待确认；不能用本次输出题数自证完整 |
| 2. 文档提取 | 文本PDF直接提取，扫描页进行OCR，保留原页、位置、识别稿及校正记录 | 题干、选项、答案、解析、正文及其来源；识别冲突待复核 |
| 3. 原文核对与分句 | 使用答案解析的完整正文和提问，固定句子ID、篇章、body/question、题号及来源页码；处理U.S.和No.等缩写 | 原文句子快照；有原文不生成ASR文字；缺原文先待补充 |
| 4. 音频规范化与定位 | 本地解码为16kHz单声道float32，记录时长、PTS及偏移；定位各篇和逐句搜索范围 | 原音与波形哈希、粗搜索范围；搜索范围不是最终起止，不得平均分配句子时间 |
| 5. 原文强制对齐 | WhisperX在原音中定位每个原文句子，保持文字及ID，内部缩写拆分归并回来源句 | 原音绝对起止毫秒、字符依据、逐句表和字幕；缺字/无法对齐/回退保留异常，不造时间 |
| 6. 对齐后用户确认 | 默认stop_after=align，保存产物后进入awaiting_confirmation | 默认停止点；本次用户已明确授权第7—8步，使用独立下游任务复用核验后的对齐。独立300ms核听结论不因此升级 |
| 7. 题目组装 | 用户确认后，合并原文题干、原卷A—D选项、标准答案和解析，建立原卷映射 | 题目草稿；缺少提问原文不根据选项猜题干 |
| 8. 关联标注 | DeepSeek从确认词典选择主要技能及有依据的扩展候选，引用已有正文句子ID并说明依据 | 主要技能及证据、答案证据；时间由程序从句子取得，模型不生成时间或标准答案 |
| 9. 检查及待审入库 | 校验字段、词典、主外键、时间、题号/选项映射、证据归属和完整性；合法结果写入非当前pending批次 | 保留自动初稿、失败及异常，旧当前批次不变 |
| 10. 最终复核与读取 | 完成逐题、整套核听及标注语义复核，修正后重检；管理员确认切换，再独立确认学生可见 | 同批次题目、证据和音频由模块二接口按权限读取 |

文字来源默认reference。原文缺失或未核对时先保存待确认任务；仅明确选择无原文模式才执行ASR，并单独记录识别初稿、方法及内容复核。有完整原文时，ASR识别文字不得替代正文和题干。本套历史ASR词时间仅复用为搜索线索，不重新转写，也不把粗定位当作正式边界；新材料的搜索范围可另行定位或核对，不要求先产生ASR全文。

原文、分句或音频搜索范围改变时须重对齐，相关证据和复核结论失效。原文中的少数OCR错误可对照原页校正并留痕，但不能以人工逐题重录替代整套自动链路验收。结构成功、对齐成功与内容/300ms精度通过分别记录。

对齐确认、确认切换当前批次、确认学生可见是独立动作。用户当前仅授权推进到对齐确认点；本次文档同步不授权继续下游标注、入库或切换。

## 六、题目、技能与证据标注需求

### 6.1 标注方式

题目字段、标准答案、解析和正文来自材料；DeepSeek API只生成结构化整理及技能、证据等候选，结合规则检查和人工复核，不代替原文来源。

| 环节 | 采用方式 | 输入与输出边界 |
|---|---|---|
| 文字来源（默认） | 答案解析/可靠原文提取，必要时OCR及原页核对 | 正文、录音提问及来源快照；已有完整原文时不运行ASR，不根据模型判断改写原文 |
| 原音转写（可选） | 仅显式选择无原文模式时用本地faster-whisper | 单独保存识别初稿、参数及复核；缺原文不能静默启动 |
| 文本与时间对齐 | 本地WhisperX CPU强制对齐 | 输入固定原文句子及音频搜索范围，输出句级绝对毫秒；搜索范围不是边界；无法对齐不造时间；原文变化后重对齐 |
| 对齐后确认 | 逐句表、字幕、原音及核听记录 | 默认停在align，人工核听后明确继续，不能凭时间字段存在就判定≤300ms |
| 字段整理与关联标注 | 确认后调用DeepSeek API | 提供可靠正文、题干、选项、来源答案解析、句子ID及确认词典；输出技能编号、证据引用、理由和有依据的扩展JSON |
| 检查与保存 | 本地规则及入库服务 | 核对真实编号、字段、引用文字和归属；时间由程序从有效句子取得；保存初稿、异常与修正 |

每个任务固定文字来源模式、原文和分句哈希、对齐模型、API型号、提示词、字段、词典和方法版本；ASR路线另记录转写模型及参数。版本依据10.6。原始音频留在本地，不向DeepSeek上传；模型不得覆盖来源答案、猜时间或临时创建词典编号。

密钥从受控配置读取，不写入文档、聊天或日志。已确认预算：5题小样≤0.50美元、单套≤2美元、阶段累计≤5美元，失败和重试纳入累计；实际调用记录模型、用量、费用和原始响应。本套当前原文对齐阶段ASR和DeepSeek调用均为0；后续收费调用仍须检查配置、预算和阶段授权。JSON合法不等于标注语义正确。

### 6.2 关系写入规则

| 关系或对象 | 写入要求 |
|---|---|
| 题目与技能 | 在 `07C_skill_question` 写入 `QUESTION_SKILL`，引用真实题目与技能 ID |
| 主要与辅助技能 | 一题可关联多个技能，各建独立关系并附证据；区分 `PRIMARY`、`AUXILIARY`；默认一个主要技能，共同主要时说明理由 |
| 正文证据 | 在 `08_evidence` 保存原文、片段编号及音频时间 |
| 技能证据 | 在 `07C_skill_question` 写入 `SKILL_EVIDENCE`，通过 `owner_relation_id` 指向对应技能标注行 |
| 答案证据 | 在 `07D_other_relation` 写入 `ANSWER_EVIDENCE`，与技能证据分别维护 |
| 候选错因及证据 | 在 `07B_error_question` 使用 `QUESTION_ERROR_CANDIDATE`、`CANDIDATE_EVIDENCE` |

同一标注有多条证据时，用多行引用并保留顺序。证据必须属于同篇正文片段，不能将录音提问片段当作正文依据。候选错因仅表示题目可能诱发的误解，不表示某个学生已被诊断为该错因。

系统按真实 `skill_id` 关联，保留显示编号与旧编号映射。解释文档中的连续 S 编号与试填工作簿原编号存在差异，不得混作主键；正式主键由程序统一分配。

### 6.3 最小必交数据

- 完整题目、题干及选项。
- 来源明确的标准答案与解析。
- 原卷题号及选项映射。
- 每题至少一个主要技能及其支持证据。
- 每题答案证据。
- 支撑接口读取和来源回查的试卷、音频、篇章与正文片段。

每条实际输出的技能关联均须有支持证据。辅助技能、候选错因、语言点及体裁等扩展标注有依据才生成，不要求每题、每种关系都有记录；无法判断时可留空待审。但采集结构中的必填字段仍须满足，已有合法“未判定”值的字段可如实使用，不得将空缺伪装成确定判断。

### 7.2 原卷映射规则

一期每套材料独立建立内容组，以本套原卷为基准，经核对后保存明确的题号和选项恒等映射；跨卷共享与重排复用后置。整卷接口须通过 `13_presentation` 对应结构读取本套题号及映射。

同年份或同名音频不能证明题目与选项顺序相同，不能直接复用另一套答案字母。映射不明时不得默认完全一致，也不得将未知映射伪装成恒等映射。

明确区分 `questions.question_index`（来源卷题号）与 `presentations.question_no`（本套展示题号）。`option_letter_mapping` 的方向为“本套展示字母 → 题库底层字母”，键和值均须为 A—D 的一一对应，不能只检查键齐全。生成映射后检查实际组装的四个选项均非空。

数据库 `questions.correct_option` 保存底层选项答案；当前 `develop` 的管理员接口已区分 `correct_option`（本套展示答案）与 `correct_option_base`（底层答案）。模块三须保持这一语义，不再重复换算或直接照搬另一套答案。本期样例仍用核对后的恒等映射；非恒等映射作为已有接口的回归边界验证，不扩展为跨卷复用功能。

### 7.3 自动处理结果接入格式

现有导入工具接受 `exam_paper`、`audio`、`content_groups`、`passages`、`transcript_segments`、`questions`、`presentations` 七段结构，通过 `_src_id`、`passage_src_id`、`question_segment_src_id`、`question_src_id` 等临时引用建立数据库主键映射。

模块三须在自动提取和校验后输出兼容现有字段语义的结构化结果，复用或重构公共校验、映射和入库服务；现有脚本不能原样作为模块三全部入库实现。技能、证据和关系须通过同一套临时 ID → 正式 ID 映射接入，并显式绑定本次批次，不能将模型生成的临时编号或历史试填 ID 当作正式外键。

现有导入器会在写入结束时直接激活当前批次，且失败回滚不会留下完整的失败业务草稿；模块三须补足“待审草稿保存—检查与规定复核—管理员确认—整体切换”的边界，防止字段或必交关系尚不完整时自动覆盖当前数据。后台处理结束不自动切换当前批次。

当前材料哈希只覆盖上述七段，不覆盖尚不存在的技能与证据结构。模块三的批次内容指纹须覆盖会影响业务结果的原件哈希、结构化内容、关联证据、字段/词典及标注方法版本；不同词典、提示词、模型版本或校正结果的重跑须可区分，不能误判为已导入无变化。相同有效结果的重复入库须可幂等复用，并另行保留任务执行记录。

### 7.4 应有题量与可信来源

复用当前 `develop` 已有的 `expected_question_count` 和 `expected_question_count_source`，后者记录 `document`、`sha256`、`locator`。应有题量来自原卷核对及可信材料登记，不能用 `len(questions)` 或当前数据库已有题数自证完整，也不能对所有试卷固定写 25。

首次处理未建立可信基准时，可保存待确认材料或草稿，但最低内容检查不得通过、不得确认可见。已有基准与本次申报冲突时须明确报错，不能由新批次静默改写。题目数、原卷映射数、题号范围与题组覆盖均须对照原卷检查。

这两个字段及 `0003_exam_paper_expected_count`、`0004_expected_count_source` 迁移已进入 `develop`，不是模块三待补能力。`0004_expected_count_source` 会使无来源的旧题量与旧检查结论失效，不能仅按旧数据数目回填后恢复开放。新开发或部署环境按既有迁移链升级；本次未检查任何运行数据库实际执行到了哪个迁移版本，不把代码已合并写成数据库已升级。

## 八、批次、修正与质量控制

### 8.1 批次管理

- 每次处理或修正重跑生成独立批次草稿，保留自动初稿及校正记录。
- 新批次完成规定检查和复核后，由管理员通过受权接口明确确认，才整体切换本套试卷的当前批次；处理进程不得自动切换，接口不得混合返回不同批次的题目、证据和关系。
- 失败批次保留用于排查，不作为学生接口当前数据。
- 重跑不得向当前版本叠加重复题目。
- 现有唯一约束的业务编码须明确批次隔离实现方式，不得将重复编码直接追加到同一约束空间。

当前批次选择沿用 `import_batches.is_current` 与 `status='active'`，同一试卷至多一个当前批次。篇章、片段、题目、映射、内容组及新增关联证据须按同一批次读取；任务中的待审结果与当前题库分开查询，不能通过修改当前数据原地“临时保存”。

相同有效结果幂等重导不得改变当前批次、清除原有可见确认或叠加重复记录；不同结果的新批次成功切换后默认隐藏，须重新检查和确认可见。新批次失败时保留旧批次、旧音频绑定、旧检查及可见状态。

管理员确认“切换当前批次”与既有可见性接口的“确认学生可见”是两个独立动作，不能复用一次可见确认同时执行版本切换；具体接口契约在开发设计中冻结。确认切换须核查目标任务、批次及对应检查结果，保留操作人和时间。

### 8.2 音频及数据库回滚

数据库回滚不等于文件回滚。新音频须采用独立版本或安全暂存，不覆盖当前批次及历史批次仍引用的文件；复用已有同哈希版本时不得将其标记为本次新建并在失败清理时删除。文件发布或数据库提交失败后，只清理本次实际创建且未被有效数据引用的临时或新建文件。

既有 `audio_code` 与文件哈希、路径、时长等冲突时须明确拒绝，不能静默复用旧音频记录。受控音频根目录沿用实际配置 `AUDIO_STORAGE_DIR`，材料登记与读取均须确保引用位于受控目录内，不能让文件名越界。

### 8.3 修正与追溯

保存材料来源、中间结果、所用版本、检查结果和失败原因，供接口及处理工具查询。人工修正须保留自动初稿、修改内容与来源记录；题目或片段修正后，重新检查受影响的证据与关联。

校正记录须能回查修改前后内容、修改对象及批次、执行人、时间和依据。现有 `review_status` 只是状态字段，不能代替实际复核记录；自动生成内容不得直接写为“已通过”。正文、题干或时间边界发生改变时，原证据及关联须重新检查或明确置为待确认，不能沿用旧审核结论。

必交内容或关系不完整时，可保存待审草稿，不能将整套标为验收通过。错误结果不能仅以“处理成功”标记代替真实质量检查。

### 8.4 接口开放与验收分别判断

处理结果检查、内容审核、学生接口可访问、整体验收属于不同维度。无效题序、选项映射、缺失题目和无法有效读取或解码的音频须阻止整套内容向学生接口开放。允许学生接口读取某套试卷，不代表其待审标注审核通过，也不代表模块三验收通过。

| 状态维度 | 现有承载或模块三增量 | 不得混同的结论 |
|---|---|---|
| 任务执行 | 模块三新增任务记录 | 任务结束不表示数据通过验收 |
| 导入批次与当前版本 | `import_batches.status/is_current` | `active` 不表示可见或已审核 |
| 最低内容检查 | `content_checks.is_passed` | 只证明规定的内容可读取检查通过，不证明教学标注正确 |
| 学生可见 | `paper_visibility.is_visible` | 业务许可不代替内容与标注审核 |
| 内容与标注复核 | 既有 `review_status` 加模块三实际复核记录 | 不能靠改状态冒充真实核对 |
| 模块三整体验收 | 模块三验收结论及证据记录 | 须同时满足必交数据、自动链路和最终联调要求 |

模块三须补充现有最低内容检查未覆盖的解析来源、正文/问题片段归属、时间边界、真实词典编号、主要技能及答案证据、关系归属和复核结论等检查。扩展标注的合理空缺单独报告，不并入必交关系缺失。

## 九、验收要求与交付成果

### 9.1 验收方式

以一套材料完整、版式固定的样例，分别通过文本 PDF 与扫描 PDF／图片输入验证文档提取路径，并通过管理员接口启动原始材料处理，完整核验独立进程执行、自动提取、关联候选、复核、入库和模块二接口读取。两类输入分别保留初稿、来源、异常与质量结果，不能只验证文本提取后宣布 OCR 通过；可复用同哈希音频的有效处理结果并保留引用记录。全部核验可通过 API、独立工具、数据库查询及受控证据完成。

| 核查项 | 通过要求 |
|---|---|
| 接口启动 | 管理员可登记或引用材料并创建任务，取得任务编号；启动响应不等待整套处理结束 |
| 状态与结果 | 接口可查询状态、结果及异常，状态与实际处理结果一致 |
| 异常处理 | 用缺少必要材料等可控异常验证错误提示 |
| 权限 | 学生无权启动任务；标准答案、解析、听力原文按权限隔离 |
| 题目完整性 | 数量、题序、题干、选项与原卷对应，答案及解析来源明确 |
| 必交关系 | 每题主要技能及证据、答案证据等实际保存且完整正确 |
| 结构与归属 | 主外键、时间范围、原卷映射、正文证据归属正确 |
| 自动化与复核 | 可对比自动初稿和复核结果，不以人工逐题重录替代自动化 |
| 批次 | 批次可追溯，检查和复核后须管理员确认才切换；确认前旧当前批次不变，切换后不混用数据、默认隐藏，重跑不叠加重复题目 |
| 句级时间定位 | 原文按句保存绝对起止毫秒，证据可引用连续多句；正文起止误差分别≤300ms，全部必交正文及证据句完成核听，不要求词级时间 |
| 失败与草稿查询 | 失败或待审结果可从任务查询，不因入库事务回滚而丢失失败原因；不会变为学生接口当前数据 |
| 升级兼容 | 从选定模块二基线增量迁移，原账号、角色、题库、旧批次和操作记录保留 |
| 实际入库与读取 | 数据实际写入 PostgreSQL，模块二接口返回同套完整听力部分；受控音频请求返回正确、可解码的文件流并支持已有 Range 行为 |

最终关键字段、必交关系和证据须完整正确；疑点须完成复核，否则明确阻塞验收。合理的扩展标注空缺不要求强行补全。

只生成文本、JSON、Excel、建表或提交手工录入的既有样例，均不能单独证明自动处理模块通过验收。原有试填可作为对照材料，待复核内容不能无条件作为标准结果。

### 9.2 质量报告

|---|---|

| 自动处理耗时 | 如实报告自动链路处理耗时 |
| 人工复核耗时 | 如实报告人工复核耗时 |

### 9.5 根据模块二缺陷补充的回归场景

下表将既有验收经验转为模块三必须保持的行为。题量、映射、答案语义及音频保护修复已纳入当前 `develop`，相关场景是后续修改的回归约束，不代表这些缺陷当前仍待修复；任务、标注及草稿部分则用于验收模块三新增能力。本次不把历史修复报告当作重新执行的测试结果。

| 编号 | 场景 | 应验证的结果 |
|---|---|---|
| R01 | 首次处理少最后一题及对应映射，未建立可信应有题量 | 报告完整性基准缺失，不能确认可见；不能将 24 题自定为应有 24 题 |
| R02 | 已有可信 25 题基准，处理结果仅 24 题或题组覆盖不全 | 明确报告缺题或覆盖异常，阻止整套验收及不完整内容向学生接口开放 |
| R03 | 映射键齐全但含 `A→Z`、重复值、缺项或最终展示空选项 | 检查失败，不能确认可见，错误定位到题目 |
| R04 | 合法 A/B 交换映射 | 展示选项与本套答案同步换算，底层答案保持原义；学生响应不含两种答案字段 |
| R05 | 已有当前音频 A，处理不同音频 B 时写库中途失败 | 旧批次、旧绑定、可见状态、音频文件及哈希不变，旧学生音频仍可读 |
| R06 | 已有带哈希后缀的版本 B，被下一次处理复用，随后写库或提交失败 | 不能误删已有版本 B；新建临时文件可清理；数据库与文件一致 |
| R07 | 同一 `audio_code` 申报不同哈希、路径或时长 | 明确报冲突，不产生错误绑定、新当前批次或不可追溯文件 |
| R08 | 重复入库相同有效结果；另以不同词典/标注版本或校正结果重跑 | 前者幂等且保留可见状态；后者可区分批次，成功切换后重新确认可见 |
| R09 | 正文、题目或时间边界修正；技能缺证据、引用提问片段或跨篇/跨批次引用 | 受影响关系重新检查或待确认，必交关系不全不得整套验收通过 |
| R10 | 新批次待审、处理失败、取消可见、服务重启 | 不混用新旧内容；待审或失败结果可由管理员追溯；可见性和取消后的访问控制持久有效 |
| R11 | 缺答案/解析、缺音频、模型调用失败、无效词典编号 | 返回可定位异常并保留已有阶段结果，不猜答案、不编编号、不误标处理完成 |
| R12 | 无登录、学生或另一名管理员访问任务和材料；数据库不可用 | 未登录 401、学生越权 403；其他管理员可按统一规则管理；数据库故障明确报错，不回退为静态样例 |
| R13 | 从选定旧库迁移到模块三；旧记录缺可信题量来源 | 不损坏认证及历史题库；补核前不沿用旧检查开放；完成来源登记后重新检查与确认 |
| R14 | 管理员接口触发真实处理，查询完成状态及结果，再读取自动产生的同套听力和媒体流 | 非本地 JSON 替代；整卷与配套内容可查，音频与来源哈希一致且可解码；取消可见后学生新的详情和媒体请求受阻 |
| R15 | 同套文本 PDF 与扫描 PDF／图片分别启动处理 | 两条提取路径均实际运行，分别保留来源、初稿和质量结果；扫描结果不得以文本 PDF 的成功记录代替，派生扫描件如实标明生成条件 |
| R16 | 新批次检查与复核完成但管理员未确认切换；随后执行管理员确认 | 确认前当前批次、旧音频和可见状态不变；确认后整体切换、默认隐藏并保留操作记录；非管理员无权确认 |
| R17 | 提供完整答案原文并选择默认路径 | ASR调用为0；正文/题干文字、稳定ID及来源保持，模型不得改写 |
| R18 | 默认路径缺少原文，或提供不属于本任务的原文来源 | 缺原文待补充；来源冲突拒绝；不静默运行ASR |
| R19 | 粗搜索范围、U.S./No.缩写及对齐库内部拆分 | 最终边界由实际对齐生成，不能复制搜索范围或平均切割；固定来源句子不被误切/改写 |

| R21 | 有效时间字段但缺人工参考，或原文/搜索范围被修改 | 300ms精度保持待核听；修改使对齐和相关证据/复核失效，重新处理 |

后端回归沿用模块二的真实 PostgreSQL 与 HTTP 验证方式；自动化模拟小样例只能证明技术行为，不能替代原卷内容核对、整套人工核听或标注语义判断。测试及重跑使用隔离数据库和媒体副本，避免清理夹具或异常场景影响现有开发数据。
