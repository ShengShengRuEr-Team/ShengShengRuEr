## 2. 基线与状态口径

### 2.1 后端已具备的 6 个接口

| # | 方法 | 路径 | 角色 | 用途 |
| --- | --- | --- | --- | --- |
| ① | GET | `/api/v1/listening-papers` | 登录即可 | 列表；管理员返回全部，学生只返回可访问的 |
| ② | GET | `/api/v1/listening-papers/{id}` | 登录 + 内容权限 | 学生视角整卷（题组、题号、题干、A–D 选项） |
| ③ | GET | `/api/v1/listening-papers/{id}/audio` | 同上 | 音频二进制流，支持 `Range` |
| ④ | GET | `/api/v1/admin/listening-papers/{id}/companion` | 仅管理员 | 答案、解析、原文片段、批次与状态、审核状态 |
| ⑤ | POST | `/api/v1/admin/listening-papers/{id}/visibility` | 仅管理员 | `confirm` / `cancel` |
| ⑥ | GET | `/api/v1/admin/listening-papers/{id}/checks` | 仅管理员 | **读取最近一次持久化的检查记录**（不执行新检查） |

- JSON 接口统一外壳 `{code, msg, data}`；**③ 是例外**，返回二进制，不带外壳（见 §8）。
- 鉴权顺序固定：先 401 后 403。
- **接口契约路径（已核实）：** `docs/development/module-2/api.md`。原 `docs/api/listening-papers.md` 在最新 `develop` 上已删除（2026-11-08 用 `git ls-tree origin/develop` 确认）。

### 2.2 状态语义与页面措辞（不得混用）

| 后端字段 | 准确含义 | 页面措辞 | 常见误读 |
| --- | --- | --- | --- |
| `is_visible` | 管理员已给出**开放许可** | 已确认开放 / 未确认开放 | ❌ 不能写成"学生可以看"——许可不等于当前可访问 |
| `check_passed` | 最低内容检查最近一次结果 | 检查通过 / 检查未通过 / 尚未检查（`checked_at` 为空） | ❌ 不等于内容正确 |
| `is_current` | 该批次是否为当前数据版本 | 当前批次 / 暂无当前批次 | ❌ 现有接口无批次选择，不存在"查看历史批次" |
| `is_pending_confirmation` | 当前批次尚未开放 | 待确认开放 | ❌ 与 `review_status` 的"待确认"不是同一字段 |
| `review_status` | 内容审核状态（试卷/篇章/题目三级） | 按接口原值显示 | ❌ 不等于开放门槛，本轮没有修改它的接口 |

- 页面另起一行给出**可访问结论**：`当前可访问 = is_current ∧ check_passed ∧ is_visible`，并说明只代表服务端判定，不代表内容已人工核对。
- `is_visible=true` 而检查未通过时，页面应显示为"已确认开放，但当前不满足访问条件"，而不是报错。
- 页面**不得**把"待审核"硬编码成固定文案，一律按接口原值显示。

### 2.3 现有前端可复用部分

- 技术栈锁定：React 19.3.1 / react-router-dom 7.18.5 / antd 6.6.8 / axios 1.21.0 / Vite 8.3.5 / TypeScript 6.0.3；依赖全部精确版本。

## 4. 逐页需求

### 4.1 管理端・试卷列表

- **信息**：试卷编码、级别、年月/套别、内容范围、时长、当前批次、检查结果、开放状态、审核状态、操作。
- **状态补充**：
  - 无当前批次时，该行显示"暂无当前批次"。
  - **不显示"非当前批次"标签**：现有接口只能查当前批次，页面无法据此判断"正在看历史批次"。
- **筛选**：级别、年份两个下拉，**仅前端本地过滤**（决议 D7）。
- **空态**：`items` 为空 → "暂无试卷，请先导入题库数据"。
- **异常**：① 失败 → 页面级错误 + 重试；④或⑥ 单卷失败 → 该行状态列显示"获取失败，重试"，其余列正常。
- **不做**：列表行内快捷开放/取消（避免误操作，统一进详情操作）。

### 4.2 管理端・试卷详情

**页头**：试卷身份、批次、三个状态标签、审核状态、`mapping_source`、时长；操作按钮组（确认开放 / 取消开放 / 查看检查结果 / 试听）。

**检查结果摘要**（页内区块）：`is_passed`、`checked_at`、"必读"一句说明——**摘要放在页内区块，`issues` 明细放在抽屉**（决议 D2）。

**主体：左右分栏（决议 D4）**

- **共享篇章状态**：左右两栏共用同一个 `currentPassageId`（单一来源）。切换篇章时**同时**刷新左侧原文与右侧题目，两栏滚动各自回到顶部；不允许两栏独立切换（否则会把 A 篇正文和 B 篇答案对照）。默认第 1 篇。
- 左栏：篇章选择器（按 `passage_index`）、篇章类型、topic、scene、accent、时间范围、原文片段（序号、`segment_type`、`speaker_code`、起止时间、文本）。
- 右栏：该篇章下题目——`question_no` 与 `question_index`、题干、A–D 选项、`correct_option`、`explanation_text`、`explanation_source`、`content_state`、题目级 `review_status`。
- **答案表达规则**：同时显示 `correct_option`（本套展示字母）与 `correct_option_base`（题库原字母）。
  - 两者不同 → 提示"本套做过选项重排"。
  - 两者相同 → **只能写"答案字母一致"**，不得推断"未重排"（正确项不动时其余选项仍可能重排）。
- `content_state != 可用` 的题目高亮，并提示"该题不可用时整卷无法确认开放"。
- 窄屏（<1280px）改为上下排列，不横向滚动。

**操作规则**

| 场景 | 确认开放 | 取消开放 |
| --- | --- | --- |
| 无当前批次 | 禁用 | 禁用 |
| 尚未检查 | **可用**（点击后先执行检查：通过即开放，未通过返回问题并留下记录） | 禁用 |
| 检查未通过 | **可用**（同上；数据修正后可借此重新检查） | 若当前已开放则可用 |
| 检查通过且未开放 | 可用 | 禁用 |
| 已开放 | 禁用 | 可用 |

> **为什么不再用检查结论禁用确认：** 后端只有 `POST /visibility`（confirm）会执行最低内容检查并写入 `content_checks`，导入工具不生成检查记录。若前端以「尚未检查 / 未通过」禁用确认，新导入的试卷永远无法产生第一条通过记录，数据修正后也会被旧失败记录卡死。改为「确认即触发检查」，把判定交给后端，前端只做提示（页头 `Alert` 说明会重新检查）。

- 前端禁用只是体验，后端 400/403 仍是最终判据；错误信息原样展示，不吞掉。
- **确认失败后必须刷新 ⑥**：后端在确认失败时会提交一条新的失败检查记录，页面若不刷新会显示旧结论。
- 取消开放：二次确认弹窗，理由选填（≤255 字）；`cancel` 不以检查通过为前提。

### 4.3 检查结果（只读语义，必须写清）

| 情况 | 页面表现 | 下一步提示 |
| --- | --- | --- |
| `is_passed=true` | 通过 + 检查时间 | 可直接确认开放 |
| `is_passed=false` 且 `issues` 非空 | 列出 `kind`/`message` | 修正数据后点「确认开放」重新检查 |
| `is_passed=false` 且 `issues=[]`、`checked_at=null` | "尚未检查" | 点「确认开放」会先执行一次检查 |

- **刷新按钮只重新读取 ⑥**，不触发新检查（后端无此接口）。
- **不单独提供"重新检查"按钮**；唯一能触发新检查的动作是"确认开放"：通过即开放，未通过留下新记录并返回问题。
- 因此"尚未检查"与"检查未通过"都不再禁用确认按钮；页面用提示说明"确认会先检查"，避免误解为直接放行。
- `issues` 明细直接显示后端 `message`，不自行改写措辞。

### 4.4 学生端・可见试卷列表

- **信息**：级别、年月/套别、时长（`duration_ms` → mm:ss）、内容范围。
- **入口文案**：**"查看听力"**，不用"开始练习"；列表页顶部一行说明"当前仅支持听音频与查看题目，作答功能后续开放"（决议 D10）。
- **筛选**：本轮不做（学生端仅 1 套可见，筛选无意义）。
- **空态**：`items` 为空 → "暂无可查看的听力试卷，请联系老师开放"，不出现权限猜测文案。
- **禁止**：任何管理入口、"待审核/批次"等后台词。
- **未来衔接**：整卷页的播放器与题目展示组件应按可复用方式组织，任务三作答页在同一路由上扩展（选择答案、提交），本轮不实现。

### 4.5 学生端・整卷听力页（按篇章分页）

- **分页**：一次显示 1 个篇章，底部"上一篇/下一篇"，显示"第 k / N 篇"，N 取自 `passages.length`（**不是固定 8**）。首尾按钮禁用，页码不可跳转。
- **播放器**（页面级唯一实例，吸顶）：
  - 播放/暂停、当前时间/总时长、进度条、音量。
  - **整段下载后本地播放**（决议 D5）：进度条拖动是**在已下载数据内定位**，不产生新的服务端请求。
  - **翻篇不打断播放**：音频元素不随篇章卸载，`currentTime` 与播放状态保持不变。
  - 学生接口不返回篇章时间点，**不做**"翻篇跳转到该篇起始时间"。
  - 加载中显示进度类反馈；失败显示"音频加载失败，请重试"，并保留题目阅读能力。
- **题目**：当前篇章 `passage_type`、`topic`、题号（原卷题号）、题干、A–D 选项。
- **只读**：选项不可点选，无"提交/交卷"。
- **不含**：答案、解析、正文、原文片段、时间范围。
- **异常**：② 返回 404 → "试卷不存在或暂不可用"（不暗示是否存在）。

## 5. 关键交互与技术规则

1. **状态不合并**：`is_current` / `check_passed` / `is_visible` / `review_status` 分别展示；另给一行"当前可访问"结论（§2.2）。
2. **写后刷新**：⑤ 成功后重拉 ④ 与 ⑥；⑤ 失败后重拉 ⑥（可能产生新的失败记录）。
3. **错误呈现**：401 由统一逻辑跳登录；403 用 `message.error`；其余页面内 `Alert`，不用 `alert()`。
4. **加载与空态分离**：骨架屏（加载中）与空态文案不得混同。
5. **分栏共享状态**：见 §4.2，禁止两栏独立切换。
6. **字段命名**：接口层 snake_case，组件前经 `adapters.ts` 转 camelCase。
7. **列表状态补调的规模边界**：
   - 并发上限 **3**，单卷超时 **8 秒**，失败只降级该行并提供重试。
   - **试卷数 ≤ 20** 才自动补调状态；**> 20** 时列表只显示基本信息，并在页头提示"开放状态请在详情查看"。后续轻量汇总接口作为独立优化项，不在本轮。
   - ④ 返回整卷内容，属重接口；必须做请求取消（`AbortController`），页面卸载即中止。
8. **音频二进制适配**（详见 §8.2）：不复用 JSON 外壳拦截器。
9. **学生端仅只读**：组件层不引入作答状态，避免后续返工。
10. **取消开放的验收边界**：指"取消成功后，学生**重新请求**列表不再返回该卷，重新请求详情/音频被拒绝"。**不承诺**已打开页面自动下架、已下载音频被远程收回（见 F08）。

## 7. 非功能约束

1. 复用现有布局、守卫、axios 封装；不重写登录与鉴权。
2. 页面路由懒加载，延续 `React.lazy` + 单 `Suspense`。
3. 只用 antd 现有组件，不引入 UI 框架、CSS-in-JS、播放器库。
4. 不渲染不可信 HTML；原文按纯文本 + `white-space: pre-wrap`。
5. **宽度规则**：≥1280px 正常两栏；1024–1280px 上下排列；<1024px 不保证布局（不做横向滚动的"伪支持"）。
6. 大文本区域可滚动；165 条片段量级不引入虚拟滚动。
7. 不做埋点、国际化、深色模式。
8. 筛选条件在返回列表时保留；页面刷新、重新登录后清空（不做持久化）。

## 8. 接口字段与音频适配

### 8.1 使用的字段

| 接口 | 关键字段 |
| --- | --- |
| ① | `exam_paper_id`、`exam_paper_code`、`exam_level`、`exam_year`、`exam_month`、`paper_set`、`content_scope`、`audio_url`、`duration_ms` |
| ② | 同上 + `passages[].passage_index/passage_type/topic`、`questions[].question_no/question_id/question_text/options[].label/text` |
| ④ | 全部 + `batch_code`、`is_current`、`check_passed`、`is_visible`、`is_pending_confirmation`、`mapping_source`、`review_status`、`passages[].scene/accent/start_ms/body_end_ms/end_ms/review_status`、`segments[]`、`questions[].correct_option/correct_option_base/explanation_text/explanation_source/question_index/content_state/review_status` |
| ⑤ | 请求 `action`、`reason`；响应 `is_visible`、`check_passed`、`action` |
| ⑥ | `is_passed`、`issues[].kind/message`、`checked_at` |

### 8.2 音频（③）的强制约定

现有 `client.ts` 的成功拦截器强制校验 `response.data.code`，且 `request<T>` 还会读 `data.data`。**直接用现有实例下载音频会被判为"响应格式异常"，即使后端返回 200。** 因此：

| 项 | 约定 |
| --- | --- |
| 请求方式 | 新增独立的二进制请求模块（如 `src/api/audio.ts`），`responseType: 'blob'`，**不经过 JSON 外壳拦截器** |
| 认证 | 复用同一个 token 读取与 `Authorization` 注入逻辑，不复制登录实现 |
| 401 | 复用现有"清态 + 跳登录"能力；403/404 返回结构化错误给页面 |
| 错误体解析 | 后端错误仍是 JSON，但会被装进 Blob：需 `await blob.text()` 后解析 `msg`，解析失败给通用提示 |
| 取消 | `AbortController`；切换试卷、路由离开、组件卸载即中止 |
| 对象 URL | 成功后 `URL.createObjectURL`，在卸载/重新加载/取消时 `URL.revokeObjectURL`，避免泄漏 |
| 超时 | 不沿用 JSON 的 15 秒；单独设定并在超时后给出可重试提示。**不设"必须 X 秒内完成"的硬阈值** |
| 拖动进度 | 在已下载 Blob 内定位，**不产生服务端请求**；不接受"拖动即 Range"的表述 |
| `Range` | 属接口能力，由后端验收脚本/手工请求验证（200/206/416），**不作为本页验收项** |
