## 2. 开发流程

1. 根据需求和现有工程调研，编写开发文档。
2. 将方案拆成任务卡，明确依赖和验收标准。
3. 两人独立审核开发文档与任务卡，汇总修改后交施博宇确认。
4. 每项任务由一人开发、两人独立验收，通过开发分支和 PR 交付；发现问题后修正并复验。
5. **两名验收人员均通过后，才向施博宇提交结果**，日常任务由施博宇最终合并到 `develop`；其他人同步最新代码继续开发。正式发布时按仓库现有发布流程合入 `main`。

## 3. 模块目标与阶段边界

模块二完整目标：从 PostgreSQL 读取一套试卷的完整听力部分，按原卷顺序提供试卷信息、题组、题号、题干与选项，支持音频访问，并区分管理员与学生可以获取的内容。

本文“整套试卷”“整卷”均仅指某套四六级试卷的完整听力部分，不包含阅读、写作和翻译。

**本阶段目标：复用模块一已有后端工程、身份权限与 PostgreSQL 基础设施，完成必要的业务模型与迁移，将一套真实完整听力试卷导入数据库，由接口实际查询试卷与题目、校验内容权限、读取真实音频并持久保存可见状态，为后续前端接入提供可用接口。**

| 阶段 | 范围 |
|---|---|
| 当前：模块二后端与数据库 | 业务模型和迁移、一套真实听力试卷导入、SQLAlchemy 查询、管理员与学生接口、受控音频访问、可见性持久化、必要批次记录、接口说明与验证 |
| 后续：前端接入 | 管理端题库与详情页面、学生端整卷页面、浏览器音频播放与暂停、页面交互及状态反馈 |
| 后续：模块三联调 | 材料自动提取、关联标注、异常复核、自动入库与重跑结果接入及端到端验收 |

### 3.2 样例导入与模块三的边界

本次允许将核对过的一套真实材料整理为结构化导入文件，再通过可重复执行的导入工具写入数据库；不要求从 PDF、图片或音频自动识别内容。样例整理与导入须保留来源，数据库记录必须完整可查，不能只交付 JSON、Excel 或建表脚本。

模块三负责从原始材料自动提取、生成关联标注并入库。本次样例导入用于验证模块二的真实存储与查询链路，不证明模块三完成。

### 3.3 已确认的开发前业务规则

1. **验收样例：** 优先采用已有的 2025 年 6 月四级第一套完整听力材料。核查完整性后，固定原卷、答案解析、原文、整套音频及来源清单，记录文件版本或哈希，作为本阶段验收依据；材料未核查通过时，不直接视为可验收样例。
2. **内容核对：** 在开发文档中明确内容核对负责人及核对任务，逐题核对全部题干、选项、标准答案、解析与原文的对应关系，并核听整套音频。保留真实核对人员、范围、结果和问题修正记录。历史试填中的自动转写、时间对齐及待审核记录不能直接视为人工审核通过；本次确认规则不表示上述核对已经完成。
3. **取消可见：** 本期提供管理员取消学生可见的操作，持久保存状态与操作记录。取消后，学生后续试卷列表不再返回该卷，详情与音频请求均须拒绝访问；已经返回给客户端的内容不属于服务端可追回范围。
4. **新批次可见性：** 新批次默认对学生不可见，成为当前批次时不得继承旧批次的可见确认，须检查通过后由管理员重新确认。新批次导入失败时，原当前批次及其可见状态保持有效；重复执行同一份材料的幂等导入不应被误当作新批次切换。
5. **管理员管理范围：** 本期所有管理员均可管理全部题库，包括查询配套内容、确认可见和取消可见；不增加仅能管理本人导入试卷的归属限制。

## 4. 后端功能需求

### M2-B01 试卷列表与基本信息

1. 提供管理员和学生所需的试卷列表、试卷详情查询能力。
2. 返回可识别试卷的信息，包括级别、年份、月份、套别，并明确内容范围为“听力部分”。
3. 本期所有管理员可查看全部数据库试卷及必要状态，不按导入人限制管理范围；学生只能查询符合展示条件的试卷。
4. 对不存在的试卷、无权访问及无可用数据等情况，按现有工程规范返回明确结果。
5. 试卷与题目接口必须实际查询 PostgreSQL，不能以写死响应、本地 JSON 或内存数据替代正式查询。

### M2-B02 完整听力部分与原卷映射

1. 至少准备一套完整听力样例，返回其全部题组、题号、题干和选项。
2. 保留明确的题组顺序、原卷题号、选项标签与选项顺序，不以内部 ID 或偶然存储顺序替代原卷映射。
3. 题目总数以选定样例原卷为准，不自行假定固定数量。
4. 区分听力正文和录音问题对应的题干；学生可以获取题干，不能获取听力正文。
5. 通过 `13_presentation` 等结构读取本套映射，不混用其他套卷的题号、选项顺序或答案字母。

### M2-B03 管理员配套内容

1. 管理员详情接口可返回标准答案、解析和听力原文，内容与样例题目对应。
2. 保留当前批次标识、最低内容检查、可见性、待确认等必要状态，便于后续页面接入。
3. 检查通过、学生可见、标注审核通过和模块三整体验收通过分别表示，不合并为一个“完成”状态。
4. 本阶段不建设技能、证据等复杂标注编辑接口或完整处理任务接口。

### M2-B04 身份与内容权限

1. 复用模块一的身份认证和管理员、学生角色，不重新实现登录体系。
2. 管理员专属查询和可见性操作只允许管理员调用。
3. 学生接口只返回学生可见字段，不将答案、解析和原文返回后再交给前端隐藏。
4. 学生直接请求管理员接口、不可见试卷或其音频时，同样执行权限检查。
5. 本阶段不向学生提供含答案、解析及原文的原始资料下载能力。

### M2-B05 音频读取

1. 提供与试卷绑定的、实际可读取的样例音频，不能只返回无效文件路径。
2. 音频访问权限与试卷访问条件一致，读取文件时复用身份和内容权限判断。
3. 音频文件可存放在本地受控目录，数据库保存文件引用、哈希、时长及与试卷的绑定；不要求将音频文件本体写入数据库。
4. 文件缺失、不可读取或绑定错误时，返回明确结果。
5. 本阶段须验证接口返回的是可解码、可实际播放的对应音频，可使用现有播放工具核听；业务页面的播放器与暂停按钮留到前端阶段。

### M2-B06 可见性与检查结果

1. 根据实际数据库记录和文件可用性计算最低内容检查结果，覆盖可展示、未确认可见及检查未通过等情况。
2. 学生访问同时满足：当前批次、最低内容检查通过、管理员确认可见。
3. 提供管理员确认可见和取消可见的操作，将状态写入数据库；学生后续列表、详情及音频请求立即反映该状态，服务重启后仍有效。取消可见后列表不再返回该卷，详情及音频请求拒绝访问。
4. 检查未通过时阻止确认可见，返回缺题、题序错误、选项映射异常或音频不可用等具体问题。
5. 本阶段至少实际检查完整题量、题序与选项映射、必要展示字段和音频可用性；不要求实现模块三的语义标注与证据自动检查引擎。
6. 可见性、检查结果和必要操作记录持久保存，不联动修改标注审核或模块三验收状态。
7. 新批次默认不可见，不继承旧批次的可见确认；仅当前批次检查通过后才能确认可见。取消可见不以最低内容检查通过为前提。

### M2-B07 批次与数据一致性

1. 样例导入保留来源、批次标识及当前批次记录，一次整卷查询中的题组、题目及音频引用属于同一批次。
2. 学生查询不混入其他草稿或失败批次，不叠加重复题目。
3. 导入应整体成功或回滚；失败导入不能污染当前可用数据。必要的当前批次设置按整套试卷执行，不能逐题混合。
4. 本阶段不建设模块三自动处理重跑或完整历史版本管理平台，但须保留后续接入所需的批次和来源关联。
5. 新批次导入失败时，原当前批次及其可见状态保持有效；切换到不同的新批次后，须对新批次检查并重新确认可见。同一份材料的幂等重复导入不得无故切换批次或清除已有可见确认。

### M2-B08 数据库与真实样例导入

1. 使用 PostgreSQL、SQLAlchemy 及现有 Alembic 迁移机制，新增支撑本阶段需求的业务结构、主外键和必要唯一约束。
2. 导入一套真实完整听力试卷，包括试卷信息、篇章或题组、全部题干和选项、标准答案、来源明确的解析、听力原文、原卷映射及正确绑定的整套音频。
3. 导入工具须说明输入格式、运行方式、材料来源及校验结果；重复执行同一份导入不得叠加重复试卷、题目或关系，具体幂等策略在开发文档中确定。
4. 字段缺失、外键错误、映射异常或文件缺失时给出定位信息，不能用占位答案、解析或虚构原文通过验收。
5. 本阶段不强制生成技能与证据等自动标注结果，不将这些结果缺失视为模块三已经通过；业务结构仍按现有 16 表基线对齐。

## 5. 技术与字段约定

1. 后端沿用 RuoYi-FastAPI，复用模块一已有工程结构、认证、权限、错误响应及日志规范。
2. 题库数据、可见状态和必要批次记录实际保存于 PostgreSQL；JSON、Excel 等可以作为导入材料或测试辅助，不能替代数据库成果。
3. 通过独立数据访问层执行 SQLAlchemy 查询，不在接口处理代码中写死整套题目；同一接口的数据和状态须来自一致的当前批次。
4. 管理员与学生分别定义返回内容，明确受限字段的处理规则。
5. 数据及可见性在服务重启后保留，迁移和样例导入应能按说明在另一套开发或测试数据库复现。
6. 验收使用真实材料核对，并清楚记录人工整理、导入及检查过程，不将样例导入表述为模块三自动处理成果。
7. 数据结构参考现有 16 表业务基线，不要求为每张表开发独立接口。主要参考试卷、音频、篇章、原文片段、题目、内容组和原卷映射结构。

## 7. 本阶段验收标准：后端与真实数据库

**通过条件：一套真实完整听力试卷实际导入 PostgreSQL，后端从数据库查询并返回正确内容，权限和可见性有效，真实音频可读取并播放，重启后数据和状态保留。每项任务须两名验收人员均通过，才向施博宇提交结果。**

| 编号 | 场景 | 通过标准 |
|---|---|---|
| B01 | 工程集成 | 复用模块一后端与认证权限，不重做登录 |
| B02 | 数据库与迁移 | 在开发或测试 PostgreSQL 执行迁移与导入，能查到真实业务记录；接口查询结果与数据库一致，不由静态响应替代 |
| B03 | 整卷完整性 | 对照选定原卷，全部题组和题目完整，题干、题号及选项顺序对应 |
| B04 | 管理员内容 | 管理员可查询标准答案、解析、听力原文及必要状态 |
| B05 | 学生字段 | 学生返回内容不包含标准答案、解析和听力原文；录音问题题干正常返回 |
| B06 | 接口权限 | 学生不能调用管理员专属接口、修改可见性或读取不可见试卷；管理员管理全部题库，不按导入人限制 |
| B07 | 音频 | 可实际读取、解码并核听绑定正确的整套音频；学生不能绕过试卷权限读取音频 |
| B08 | 可见性 | 确认与取消操作及必要记录持久保存；检查未通过时拒绝确认并说明原因，但允许取消可见；取消后学生列表不再返回该卷，后续详情与音频请求拒绝访问 |
| B09 | 批次与状态 | 整卷数据属于同一当前批次，不混入草稿或失败批次；新批次不继承旧批次可见确认，须检查并重新确认；导入失败不影响原当前批次及其可见状态；可见性不改变其他审核和验收状态 |
| B10 | 异常处理 | 不存在、无权访问、空数据及音频不可读取等情况均有明确响应 |
| B11 | 字段与对接 | 来源字段、接口字段、类型与角色可见范围对应明确，接口和音频访问说明足以支持后续前端对接 |
| B12 | 双人验收 | 两名验收人员分别记录结论；存在未通过项时修正并复验，均通过后再提交施博宇 |
| B13 | 导入可靠性 | 相同材料重复导入无重复记录，不无故切换批次或清除已有可见确认；可控错误导入失败后不留下半套试卷、不污染当前数据 |
| B14 | 持久化 | 重启后端后，试卷、题目、批次和可见性仍可正常查询；断开数据库时明确报错，不回退到写死样例伪装成功 |
| B15 | 模块一回归 | 新增迁移与功能不破坏已有账号、登录、退出、角色及基础鉴权 |
| B16 | 样例内容核对 | 样例材料与来源清单固定，全部题干、选项、答案、解析与原文对应核对，整套音频完成核听，附真实核对与问题修正记录；历史待审核试填不直接作为人工审核通过依据 |

本阶段不以业务页面、浏览器播放器交互或模块三自动识别入库完成作为通过条件。真实数据库、完整试卷和实际音频读取为必交内容；后端与数据库阶段通过不等于模块二前端及三个模块端到端验收通过。

## 8. 后续联调要求（本阶段不实施）

1. 接入 React 管理端和学生端，完成整卷页面、浏览交互及实际播放和暂停。
2. 前端直接对接本阶段已实现的数据库查询、可见性和受控音频接口，验证页面与接口权限一致。
3. 以真实用户、试卷和媒体验证接口权限，确认学生无法获取答案、解析及原文。
4. 对真实记录检查题目完整性、原卷映射、当前批次与最低内容检查，确保不混用批次。
5. 接入模块三实际自动处理并入库的同一套试卷，完成端到端验收；本次人工整理样例的导入不替代自动处理验收。

1. 模块二后端源代码、SQLAlchemy 业务模型、Alembic 迁移及对应开发分支、PR。
