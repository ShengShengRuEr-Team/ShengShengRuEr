## 0. 使用说明与签认状态

1. **本文规定“做什么、哪些行为不可发生、如何验收”**，不规定具体表结构或接口实现；实现设计见[《错题本模块开发文档》](../../development/wrong-book/development.md)。
2. 上位需求明确：收集用户做错的题目形成**个人错题记录**；能查询、查看、管理；显示当次作答、正确答案、解析及既有配套内容；展示关联技能、候选错因和依据；**个人错因只能按实际确认情况展示**。
3. 上位需求并未明确“同题多次做错如何计数、删除含义、已掌握状态、筛选维度、无效旧卷可见性”等细则。本文将这些列为 **【拟定实施口径｜待负责人确认】**。未经签认不能宣称这些为已批准业务规则。
4. **重要门禁：** 既有学生题库接口禁止直接提供正确答案、解析及听力原文；既有作答系统 API-3 只提供提交汇总，没有逐题结果接口。错题详情若展示答案、解析，必须取得相应受保护结果读取能力的业务/安全授权与题库内容治理门禁。**不得以前端隐藏、直接查数据库或独立错题接口绕过该限制。**
5. 开发人可以完成不含受保护内容的底层数据归集、权限和测试；涉及受保护内容的对外接口及学生页面放行以前述门禁为前提。

## 1. 项目目标与业务范围

### 1.1 目标

学生完成一套英语四/六级听力试卷并成功交卷后，系统依据服务端判分事实，把答错或未作答的题目纳入该学生的个人错题本。学生能够找到、区分和复习自己的错题，查看可合法开放的答题反馈及相关技能/候选错因，并管理复习进度。结果要跨浏览器和后端重启持久保存。

### 1.2 本轮应交付的能力

| 功能编号 | 功能 | 核心产出 | 性质 |
|---|---|---|---|
| WB-F01 | 自动归集 | 成功提交的错误/未作答题目产生个人错题事实 | 上位要求的必要实现 |
| WB-F02 | 我的错题列表 | 查询本人错题、空态、分页及必要筛选 | 上位要求；具体筛选为拟定 |
| WB-F03 | 错题详情 | 题干、选项、当次答案、正确答案、解析及可用配套 | 上位要求；受保护内容有放行门禁 |
| WB-F04 | 技能与错因 | 展示可用且合规的题目关联技能、选项级候选错因及依据；与个人确认区分 | 上位要求；需与模块三数据规则对齐 |
| WB-F05 | 错题管理 | 复习标记、隐藏与恢复、重新检索 | “管理”要求下的拟定交互 |
| WB-F06 | 版本与隔离 | 本人数据隔离、历史快照一致性、旧卷处理 | 必须满足的安全/一致性约束 |
| WB-F07 | 端到端验收 | 接口、数据库、页面、权限、回归与证据 | 必要质量要求 |

### 1.3 不在本轮范围

- 重新开发登录、整卷练习、交卷、判分、音频管理、题库发布或题库内容编辑。
- 修改技能/错因词典分类，或者让错题本编辑题目的官方标准答案、选项与标注。
- 自动认定学生的个人真实错因；AI 自动诊断、推荐算法、DKT、智能学习路径。
- 创建新的独立作答记录、修改原始判分、允许通过“复习”绕过同卷限次。
- 服务端答题草稿、跨设备进行中的答题同步、手机端专项适配、离线学习、错题导出。
- 教师/管理员查询所有学生的个人错题统计或代学生修改记录。

## 2. 现有系统依赖与权限前提

现有代码已具备学生角色鉴权、整卷读取、一次成功提交、服务端判分与以下持久化事实：`attempts`（成功提交）、`attempt_answers`（每题作答快照）、`attempt_rejections`（失败提交标记）。`attempt_answers` 包含原卷题号、题干、选项快照、正确答案、学生所选（可为空）、解析与 `is_correct`。现有 API-3 `GET /api/v1/listening-papers/{id}/attempt-status` 仅有提交汇总，不含逐题内容。以上是代码核对结果，不表示错题本已经实现。

**准入规则**：仅登录学生查看本人记录；管理员不因管理题库而有查看学生个人作答的权限。对已提交记录的受保护内容仍执行**查询时准入**：目标试卷当前学生可访问（当前活动批次、最低内容检查通过、管理员确认可见）及本人所有权。后台保留历史记录不意味着学生始终可读取其答案。

## 3. 术语与数据口径

| 术语 | 含义 |
|---|---|
| 成功提交（attempt） | 服务端完成整卷判分并持久化的一次提交，不包含草稿/失败/拒绝标记 |
| 错题发生事实 | 某次成功提交中的一题，`is_correct=false`；即使该题未作答也纳入，但需区分类型 |
| 答错 | 当次选了 A–D 之一，且与服务端判定答案不一致 |
| 未作答 | 当次 `selected_option=null`，判分计错；显示为“未作答”，不得伪造某个选项 |
| 错题记录 | 一次成功提交中的一个错误题目事实，与该次作答快照绑定 |
| 个人复习状态 | 学生对错题的复习管理标记；不是原始判分，也不代表答题正确率变化 |
| 题目技能 | 题库给该题关联的三级技能，可有主要/辅助角色，须遵守词典和标注的有效性 |
| 候选错因 | 题库针对某个**具体错误选项**及其证据的潜在误选机制，不是学生已被确诊的错因 |
| 个人确认错因 | 需要独立的、可追溯的确认来源；没有确认记录时应为空/未确认 |
| 题库版本 | 该次作答使用的导入批次；题目快照与其来源版本相符 |

## 4. 业务规则（需求级）

### WB-BR01：归集触发和范围

- **错题事实只随服务端成功提交事务产生**。客户端勾选、页面跳转、草稿保存和未成功提交均不产生错题事实。客户端响应超时不能单独触发归集，也不能据此判定事务失败；事务若已成功，保留该次提交及其唯一的逐题错题记录，同键重试不重复生成。
- 成功提交的每一题读取服务端持久化 `is_correct`：`false` 纳入；`true` 不纳入。`selected_option=null` 仍为错题，另以“未作答”区分。
- 不重新比较选项字母、不从当前题库重新判分；归集与该次提交的快照一致。
- 幂等重放同一成功提交不重复归集；并发请求不得为同一发生事实产生两条记录。
- 旧的已成功作答记录需有可复现的补录策略，不因部署错题本而丢失历史错题。

### WB-BR02：记录唯一性与多次作答【拟定实施口径｜待确认】

- 唯一“发生事实”按 **`attempt_answer`** 区分。同一道题在不同合法成功提交中再次答错，保留不同发生事实；列表默认按发生次数逐条显示，**不跨卷/跨批次合并**。
- 当前系统执行**同一学生同卷最多一次成功提交**；错题本不能自行改动这个限制。“再次做错”仅适用于未来正式允许多次提交时的兼容性，不表示本轮开放重做。
- 未来如增加“以稳定题目身份聚合错题次数”的功能，需新需求及跨批次等价判定规则；本轮不做。

### WB-BR03：错题列表【拟定展示细则｜待确认】

- 默认显示本人未隐藏错题，按交卷时间倒序，其次按原卷题号排序。每条至少显示：考试级别/年份/月/套别、题号、错题类型（答错/未作答）、交卷时间、个人复习状态；列表不默认输出正确答案、解析或原文。
- 支持分页、空状态、加载错误后重试；建议支持按试卷、错题类型、复习状态筛选。搜索题干关键词、技能筛选留二期，避免脱离现有权限和标注成熟度。
- **只可查看当前满足学生访问条件的记录**。旧卷下线时，相关记录仍保存在后台，但学生列表不返回其详情或作答内容；恢复访问后重新出现。
- 隐藏管理获批后，列表支持默认仅可见、仅隐藏和全部三种查询模式。服务端先按身份、试卷访问条件及所有筛选项过滤，再分页；总数与当前筛选一致，符合条件的未作答也计入。

### WB-BR04：错题详情（受保护数据）

- 在“本人、成功提交、该试卷查询时学生可访问、受保护结果读取能力已获批准并开放”的条件**全部满足**后，才允许返回当次作答快照，包括：原卷题号、题干、原卷顺序 A–D 选项、学生所选（未作答为 null）、正确选项、解析（可为空）。
- 详情展示明确标注“**交卷时内容快照**”，不能悄悄使用修改后的当前题目或最新标准答案重写旧记录。
- 有合法受控音频可供访问时，按模块二现有权限读取当前卷音频，并标明音频来源。当前批次与交卷来源批次一致且能确认音频对应时才提供播放；换批、无法确认对应或下线时暂停提供入口，按开发文档刷新或关闭播放器。不得复制原始音频、提供公开直链或把当前音频标为交卷快照。
- 解析没有内容时显示“暂无解析”。有历史解析的记录须核验授权覆盖实际要输出的交卷快照；当前卷可访问或当前解析已审核均不能替代对历史快照的核验。历史解析未覆盖时仅在其他字段获准的情况下显示“历史解析暂不可查看”，并保留不可变快照。其余受保护字段未获准时关闭详情。
- 对涉及原文的题干、解析及证据，遵循正文保护规则；未经授权不得下发原文全文、片段、时间轴或可反推出原文的文本。
- 详情权限未放行时，明确显示不可查看/暂未开放，不回退为未经授权的原始题库查询。

### WB-BR05：技能、候选错因与个人错因

- 题目技能只显示符合当前业务标注规则、三级词典及关联版本的有效结果；展示主要/辅助角色。没有有效关联时显示“暂无已审核技能标注”。
- **错因必须按具体错误选项关联**：若学生选错 B，只能尝试显示该题**B 选项**合规、可用且已审核的候选错因；不能把 A/C/D 的候选错因一起当作 B 的归因。未作答时不凭空选择某个选项错因。
- 候选错因可以为 0 个或多个；0 个时显示“暂无候选错因”，不能把空结果写成系统已证明学生没有错因。
- 显示“题目候选错因（不代表个人已确认）”，列出代码、名称、适用说明、合规可显示的依据；不把 AI 候选转成“你的真实原因”。
- 与模块三有效规则门控对齐：旧版错因只留审计，不在学生查询链路降级显示；未审核、版本不符、证据无效、候选评估失败或缺失时隐藏对应候选并给中性缺省提示。
- 本轮**不新增个人错因确认操作**。若未来接入已确认的个人错因，应另有用户/审核主体、确认时间、方式和来源证明；当前为空时必须写“未确认”，不可自动补齐。
- 关联应与**作答来源批次**匹配；当前卷已换批时，不得把不同批次或不同选项映射的技能/候选错因拼接到历史作答。

### WB-BR06：个人错题管理【拟定实施口径｜待确认】

- 支持“标记已掌握 / 重新标记待复习”和“隐藏 / 恢复显示”；允许的初始状态为“待复习、未隐藏”。
- 已掌握只更新复习进度，原始 `is_correct` 保留。隐藏后的记录从默认列表移除，可在已隐藏列表中恢复，详情在恢复后按原权限查看。原始成功提交、判分快照和历史错题发生事实必须保留。
- 操作只影响本人记录，并持久保存。部分更新仅修改明确提交的字段，并发更新复习状态与隐藏标志时应同时保留两项结果。重复设置同值不刷新状态时间，恢复显示保留复习状态及其时间。
- 无权/不存在时统一不可探知他人记录；客户端禁止自行篡改记录所属人、试卷、题目、正确答案或提交时间。

### WB-BR07：历史版本与可见性

- 题库换批、题目更正、标注变动不影响已提交时的作答快照和是否答错的结论。
- 错题所展示的技能/错因如采用“读取时有效标注”，须表明它**不是提交时冻结的标注快照**；仅允许使用同来源批次、当前符合规则的审核结果，无法证明一致则不展示。
- 试卷取消学生可见时，仍保留错题记录，但本轮学生错题列表及详情不泄露其题目、正确答案或解析；恢复后在授权条件下可重新查询。
- 题库硬删除与作答历史的外键/版本关系必须保持一致，不允许静默删除已有学习记录。

### WB-BR08：个人数据安全与权限

- 未登录：401；管理员访问学生错题接口：403；学生访问他人错题或不可见卷资源：对已认证学生统一 404（不暴露是否存在）。按现有项目约定先鉴权、再校验角色与访问范围。
- 任何查询都**从当前登录身份取得 student_id**，不信任前端传入的 student_id。列表/详情/更新均做服务端权限验证，不依赖前端路由隐藏。
- 非公开结果接口以及拒绝访问的响应均设置 `Cache-Control: no-store`；不通过日志、异常回显、公共缓存泄露个人答案、解析或正文。
- 使用参数校验和数据库权限约束，禁止用户通过分页游标、数字 ID 猜测、批量参数越权获取记录。

## 5. 页面与交互需求（桌面一期）

| 页面 | 信息与操作 | 空态/异常要求 |
|---|---|---|
| 我的错题列表 | 听力练习导航下入口；按试卷、类型、复习状态筛选；分页；进入详情 | 无错题、全部隐藏/筛选为空、加载失败、记录下线要有不同中性说明 |
| 错题详情 | 原卷题号、题目与选项、本人当次作答、正确选项、解析、可用的技能/候选错因及依据、复习管理按钮 | 无解析/无标注/未作答/旧卷无权限/音频不存在等分别处理 |
| 复习管理反馈 | 已掌握/待复习、隐藏/恢复；操作后刷新列表与数量 | 请求失败要恢复 UI 原状态，不得只在本地假成功 |

适配基线与现有前端一致：React + Ant Design、桌面主流视口，至少覆盖 1280×720 与 1440×900；1024–1279 可折叠/横向滚动；小于 1024 当前不承诺。不得新增独立第二套登录或作答页面。

## 6. 典型业务流程

1. 学生打开当前可访问的试卷，正常作答并提交。
2. 服务端完成幂等、限次、版本校验和判分，写入成功提交与逐题快照；在同一提交中产生对应错题事实；若提交失败则都不生效。
3. 学生进入“我的错题”，只看到自己的且当前允许访问的记录；可按条件检索。
4. 点开一条错题，在受保护读取门禁满足时，看到**该次**选项与结果及合法开放的配套内容；看到“候选错因不是个人确认错因”的区分。
5. 学生标记复习进度或隐藏；刷新、重新登录、重启服务后标记仍在。
6. 试卷下线/换批后，原错题事实和复习标记不变；查看权限和可显示标注严格按当时规则执行。

## 7. 异常与边界清单

| 编号 | 情况 | 应有结果 |
|---|---|---|
| WB-E01 | 题全对 | 不产生错题记录；列表为空或维持其他错题 |
| WB-E02 | 全未作答但成功提交 | 全部列为“未作答”错题，所选为 null，不造选项 |
| WB-E03 | 客户端超时后以相同键和内容重试 | 若原事务已提交，重放同一结果，保留原 attempt 与对应错题；若原事务未成功，该次请求不产生错题，后续仅在根据既有规则成功提交时归集 |
| WB-E04 | 草稿/非法提交/版本冲突/权限失败 | 不新增任何错题事实 |

| WB-E07 | 管理员直接请求错题 API | 403，不允许绕路读取学生结果 |
| WB-E08 | 取消试卷可见后查询 | 不公开题干/答案/解析；后台记录保留，恢复后按门禁访问 |

| WB-E10 | 缺技能/候选错因或解析 | 中性空态；候选不得冒充个人诊断 |

| WB-E12 | 隐藏/已掌握后刷新 | 状态持久化，不变更原始作答数据 |
| WB-E13 | 并发更新独立字段、重复设置同值及恢复 | 两项变更均保留，未提交字段不变；同值重试不刷新时间；恢复保留复习状态；无重复事实或竞态 500 |
| WB-E14 | 数据库故障/迁移失败 | 明确失败，不以浏览器缓存伪装为服务端正确结果 |
